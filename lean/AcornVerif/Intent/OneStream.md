## The restatement the owner confirmed

The owner holds Acorn's intent at the level of the research of Rich Sutton, Khurram Javed and Oak Lab and of the OaK architecture. On 2026-11-03, in conversation with the agent supervising the owner's projects, the owner was shown a plain restatement of each of Acorn's four contracts, each sentence marked as resting on that research, as the owner's own earlier decision, or as a choice the agents made on the owner's behalf, with three forks and a recommendation for each. Asked whether to confirm the contracts and all three recommendations, the owner answered: "yes, and ensure that each contract has citations and links to their sources". `docs/mission-contract.md`, section "The owner's confirmation of 2026-11-03", records that confirmation and the fork choices, and its section "Contract 3: invariants of learning from one stream" carries contract 3's restatement word for word. Without its citations and labels it reads:

1. The agent consumes its one stream as each experience arrives, in order, and stores no experience to replay as training data. It may make several internal updates per step, keep eligibility traces and plan with a model it has learned.
2. Every step does bounded work and holds bounded memory, and the bounds do not grow as the run goes on.
3. There are no special training periods: on every step of its life the agent may learn, and may plan with a model it has learned.
4. The agent is never reset: its memory carries across every attempt, every stop and every resumption.
5. A stopped agent resumes exactly where it stopped, and afterwards acts and learns as it would have without the stop, in a world that waited for it.
6. These hold on every step of every run, with no exceptions.

## Decided on the owner's behalf

The restatement leaves these open below the owner's level. Each was decided by the agent that carried out the work, unless another role is named, for the reason given; none is the owner's.

- **What the record reads of the agent: its own reports** (the subject's type, `AcornVerif.Intent.OneStream.Learner`). A subject is contract 1's subject, one world, one agent and the run that couples them, refined only as far as the six sentences need to speak of what the agent keeps and does: the memory it holds and the memory a run keeps for it, from contract 1's fields; and three reports of the agent's own, the internal updates its step makes from a memory on the experience it is given (`updates`), each of one of the closed kinds `AcornVerif.Intent.OneStream.Update` names (a learning update with its training datum, `AcornVerif.Intent.OneStream.Datum`; a planning update; a reset; any other update), the work of that step (`work`), and the memory it resumes with after a stop (`resume`). Reason: the agent's memory and answer are opaque at contract 1's interface, and no property of what an agent answers and keeps can tell a replay of stored experience from planning with a learned model, a reset from a memory that returns to its initial value by the agent's ordinary update, or the work a step does; the sentences speak of exactly these, so the record must read them from the agent's own description, as obligation 7 of the mission contract asks of an experience-consumption semantics, and the proof of the executing code (the fifth step of rbeauchamp/acorn#215) must establish that the descriptions are the executing agent's. That they are is trusted until then (below). The memory, the memory a run keeps and the memory the agent resumes with are values the record compares, so `boundedMemory`, `keepsItsMemory` and `resumesWhereStopped` constrain behaviour; `learnsOnArrival`, `boundedWork`'s bound on work, `learnsEveryStep`, `plansEveryStep` and `neverResetsItself` constrain the reports.
- **An experience arrives at the step the run gives it.** A training datum is named by how many steps before the learning update's own step the run gave it (`AcornVerif.Intent.OneStream.Datum.stream`), and "as each experience arrives" reads as `stream 0`: a learning update takes the experience its own step was given, beside short-term credit-assignment memory and learned state. Reason: in contract 1's interface an experience reaches the agent when the run gives it, and contract 1's record has the run give the agent the world's current observation and reward. A learner that learns from each experience once, in order, one or more steps after it arrived fails `learnsOnArrival` (`AcornVerif.Intent.OneStream.replaysPrevious` in `oneStream_o3`); obligation 7's "once, in stream order" is met by every learner that meets this property. The bounded-lag split rbeauchamp/acorn#90 plans (its requirement R5) lets the acting part lag the learning part; a learning part that lags the stream would fail this property.
- **"No special training periods" reads as learning on every step, if on any** (the properties `learnsEveryStep` and `plansEveryStep`). Decided on the owner's behalf by the agent supervising Acorn's research, on 2026-11-06, after the blind readings read "may" as permission (below). If the agent makes a learning update on some step a run takes, it makes one on every step every run takes, and likewise for planning updates; an agent that never learns or never plans meets them. A learning update that changes nothing counts as one, so what the properties rule out is making the update on some steps only, not an update that leaves what was learned unchanged: a learner that learns only at the steps where its reward is not 0 is ruled out (`AcornVerif.Intent.OneStream.rulesOutLearningOnSomeSteps_holds`), and its neighbour, which makes its update at every step, meets the record (`AcornVerif.Intent.OneStream.blinkerLearns_meets`). Reason: the owner holds Acorn's intent at the level of the research, sentence 3 is marked as resting on research, and the source it cites states this reading itself: "There are no special training periods when training information is available or when rewards are counted more or less than others. ... If the agent learns or plans, then it learns or plans on every time step" (Sutton, Bowling and Pilarski, [The Alberta Plan for AI Research](https://arxiv.org/abs/2208.11173v3), section "Research Vision", the passage on temporal uniformity, PDF p. 2). "May" makes learning and planning optional for an agent as a whole, which these properties keep. Both readings rule out training periods and phases in which learning is switched off, the sentence's core; the difference that remains, an agent that makes its learning update only on some experiences, is settled by that source, so the owner was not asked.
- **A memory may return to its initial value without a reset** (the consequence `AcornVerif.Intent.OneStream.returnsToInitialWithoutReset`, proved by `AcornVerif.Intent.OneStream.returnsToInitialWithoutReset_holds`). A reset is the agent's own report of an update that discards what its memory holds (`AcornVerif.Intent.OneStream.Update.reset`), not the value its memory reaches. Reason: contract 1's confirmation file found that no property of what a run does can tell an agent that clears its memory at a restart from one whose memory merely returns to its starting value, such as an agent that counts steps modulo two in a world of two-step attempts; a record that refuted every return to the initial memory would refute learners with bounded memory whose memory revisits its initial value by learning.
- **Some learner whose run takes no step meets the record** (the consequence `AcornVerif.Intent.OneStream.neverBeginsMeets`, proved by `AcornVerif.Intent.OneStream.neverBeginsMeets_holds`). The properties of steps hold of it emptily, it holds only its initial memory, and its stop before the first step asks only that it resume with that memory. Reason: that the run can begin is contract 1's property `canBegin`, which the mission contract conjoins with this record; stating it again here would add a requirement none of contract 3's sentences makes.
- **Bounded memory is a finite set of memories** (the property `boundedMemory`). One finite list holds every memory every run of the learner holds. Reason: the memory is everything the agent's answer reads, so a bound on the bits it holds is a bound on how many memories it can hold, and conversely finitely many memories need a bounded number of bits; the sentence leaves the exact bound to Acorn, and the mission contract counts capacity as memory states (condition (d) of contract 2). The bound is fixed before every run and every time, as "the bounds do not grow as the run goes on" says, and it is the learner's: each world Acorn runs is its own learner.
- **Bounded work is a bound on the reported work and on the number of internal updates** (the property `boundedWork`). Reason: the subject reports work in a unit of cost it fixes, since Lean states no semantics of executed work yet (obligation 7); each internal update is work, so the number of internal updates of a step is bounded with it, as "several internal updates per step" allows.
- **A stop is a step the run does not take, and a resumption is the run from where it stopped** (the vocabulary predicate "the run stops" and `AcornVerif.Intent.OneStream.Learner.resumedAt`). A stop is contract 1's: the run reaches a state and memory and takes no step from them. The agent resumes from the state where the run stopped, which is the world that waited for it, with the memory it reports it resumes with. Reason: contract 1's run ends at a stop and says nothing of resuming, and sentence 5 asks only that the agent resume where it stopped in a world that waited; a crash, which leaves no stop, and a world that moves while the agent is stopped are left unsaid.
- **The shape.** The subject is declared a plain value (`.value`), of which lean-intent's O4 asks nothing (`AcornVerif.Intent.OneStream.oneStream_o4`). lean-intent's shape for a description made of functions asks every function to vary with its input, and this record admits a world, an agent or a report that is constant, as contract 1's does for the same subject's world and agent.
- **Sentence 6.** Each property quantifies over every sequence of outside inputs and every step, memory or stop of the run, the record has no domain hypothesis, and a run resumed after a stop meets the record too (`AcornVerif.Intent.OneStream.resumedMeets_holds`). Reason: "every step of every run, with no exceptions" leaves nothing to assume; runs in other worlds are other learners, each to meet the record, as contract 1's sentence 8 is carried.
