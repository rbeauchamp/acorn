# Acorn's mission contract

Acorn pursues Oak Lab's mission: "Our goal is to discover and implement algorithms that allow agents to achieve goals in big worlds" [[1]](#r1).
Acorn's owner states what pursuing it means for Acorn: to prove that Acorn's agent achieves goals over a formally modelled class of big worlds.
The proof takes the form of a contract: preconditions on the class of worlds, a postcondition on achieving goals, and invariants of learning from one continuous stream of experience.
Running the agent in ARC-AGI-3 games or on the Microduck shows it working and finds defects; it is never the evidence.

This document states that contract and the decisions behind it, for contributors and their agents.
It is the contract of Acorn's mission as a whole; each [mission issue](../CONTRIBUTING.md#missions-for-outside-contributors-and-agents) freezes a contract of its own, a theorem or check that serves a part of this one.
Each of its four contracts opens with the plain restatement the owner confirmed and then gives Acorn's design below it, precisely enough that a Lean statement follows from it.
No theorem in the tree yet proves the contract for Acorn's agent; [the last section](#open-obligations) lists what remains.

Terms used throughout:

- A *world* is a deterministic state machine that hands the agent one percept per step and moves on the agent's action (`Kernel.World`). A *percept* is what the agent receives in one step: an observation frame and the reward of the preceding transition (`Percept`).
- An *agent* turns its memory and one percept into an action and its next memory (`Kernel.Agent`). Its *stream* is the sequence of percepts it receives.
- A *class of worlds* is a family of worlds, its *members*, each with its own start state (`WorldClass`). An *attempt goal* is a condition on a world's states with a step cap (`AttemptGoal`); an agent *achieves* it when its own run reaches a satisfying state within the cap (`Achieves`), and the goal is *feasible* when some sequence of actions does (`Feasible`).
- A *frozen agent* keeps nothing of what it perceives: its memory advances without reading its percepts, though its action may read the current one (`ExperienceFree`). An agent whose actions read no percept is frozen (`OpenLoop.experienceFree`).
- A *visit* is one attempt of a fixed length from a member's start state. Between visits the member's world returns to its start state while the agent keeps its memory (`Kernel.visits`); an agent *solves a member on a visit* when it achieves the member's goal within that visit (`SolvesOnVisit`). The confirmed restatements call a visit an *attempt*.
- A *covering bound* k says that one action sequence meets the goals of at most k members within the cap (`Covered`).
- The *grid world* is the tile world the viewer shows, under the name the code and proofs use.

## The mission contract

**In plain words.**
Acorn is an agent, written as running Lean code, about which one kind of theorem is to be proved.
For each stated class with its learning preconditions, consider a separate run of the same agent from the same initial memory in each member, keeping memory across that member's visits.
Learning only from its own single stream in each run, the agent eventually gains more reward per visit across the class than every frozen agent can.
Each class states its reward so that this is the same statement as solving more members per visit than every frozen agent, and Acorn proves it by the agent solving more than the class's covering bound k members on one common visit, which no frozen agent does on any visit.
Within each member's repeated visits, once it achieves the goal it keeps achieving it while the problem stays the same.
This promises class-level separation and retention, proved first as an advantage that arrives eventually, with a bound on how long learning takes as the next step; eventual success in every member is a stronger obligation that this contract does not yet impose.
The parts are the interface every world meets ([contract 1](#contract-1-the-interface-every-world-meets)), what makes a class of worlds big ([contract 2](#contract-2-what-makes-a-class-of-worlds-big)), the invariants of learning from one stream ([contract 3](#contract-3-invariants-of-learning-from-one-stream)) and what achieving goals promises ([the postcondition](#the-postcondition-what-achieves-goals-promises)).
The theorems concern the definitions that execute.

- **Source.** The mission sentence is the opening of Oak Lab's mission page [[1]](#r1). Its section "Our algorithms learn in real-time without storing or replaying data" says that Oak Lab's "batch-size-one learning algorithms can learn directly from experience without storing or replaying data". The Alberta Plan characterizes "the problem of AI as the online maximization of reward via continual sensing and acting, with limited computation", and grounds learning in experience alone: "Only experience is available to the agent, and the environment is known only as a source and sink for these signals" ([[3]](#r3), "Research Vision: Intelligence as signal processing over time", with Figure 1). Neither source states a formal criterion of success.
- **The owner's decision: a theorem, not a score.** The promise is a theorem about the executed definitions. A score measures finitely many cases, while a theorem covers every world of the class it states; [missions](../CONTRIBUTING.md#missions-for-outside-contributors-and-agents) gives the rule, with an audit that found ARC-AGI-3's public games reachable by strategies that do not learn.
- **The owner's decision: intent-first at the contracts.** On 2026-11-03, on the report of the [intent-first pilot](spec-first-pilot.md), the owner decided that contracts 1 to 3 below are where the owner's intent is confirmed. On the same day the owner confirmed their plain restatements and that of the postcondition, which became a fourth contract the owner confirms ([the confirmation](#the-owners-confirmation-of-2026-11-03)). Each of the four gets an *intent record*, a Lean statement of the contract's properties written with the [lean-intent](https://github.com/rbeauchamp/lean-intent) library from the restatement the owner confirmed. The record is proved adequate under lean-intent's obligations and compared with a second model's blind formalization of the same words, and only then is the executing code proved against it. These proofs build in Acorn's merge gate, `./scripts/gate.sh`; no rule of Regula's checks lean-intent's obligations. Everything below the four contracts, including the specification of each internal function, is the agents' design, derived from the contracts and decided on the owner's behalf. The reason: a specification that misses the owner's intent is a bug, and the pilot showed that the owner's attention belongs at a system's contracts, not at internal functions an agent invented. Contract 1 has its intent record, `AcornVerif.Intent.WorldInterface.worldInterface`, with its adequacy proofs, its blind second reading and its confirmation file, `lean/AcornVerif/Intent/WorldInterface.md`; the proof of the executing code against it is the fifth step of [#213](https://github.com/rbeauchamp/acorn/issues/213). Contract 3 has its intent record, `AcornVerif.Intent.OneStream.oneStream`, with its adequacy proofs, its blind second reading and its confirmation file, `lean/AcornVerif/Intent/OneStream.md`; the proof of the executing code against it is the fifth step of [#215](https://github.com/rbeauchamp/acorn/issues/215). The postcondition has its intent record, `AcornVerif.Intent.Postcondition.postcondition`, with its adequacy proofs; its blind second reading and its confirmation file are the third and fourth steps of [#219](https://github.com/rbeauchamp/acorn/issues/219). [#178](https://github.com/rbeauchamp/acorn/issues/178) tracks the work, with one sub-issue for each contract.
- **Acorn's choice: the comparison is with frozen agents, not with an optimum.** In a big world the agent cannot "represent the value or optimal action for every state" ([[2]](#r2), "The Big World Hypothesis"), so the optimum is no yardstick. A frozen agent is one that keeps nothing of its stream, so what learning from experience must add is to solve more members of the class on one visit than every frozen agent can on any visit. Every individual feasible goal has a frozen scripted solver (`feasible_iff_script`, `script_experienceFree`); the separation concerns one agent across the class, not a goal that defeats every frozen agent. The sources motivate the comparison (tracking can do better than every converging algorithm, see [the postcondition](#the-postcondition-what-achieves-goals-promises)); the predicate is Acorn's.
- **Open.** The mission theorem itself, for Acorn's executed agent; [the open obligations](#open-obligations) list its parts.

Two mathematical facts shape how "any big world" is read.

### No agent achieves goals in every world

- **Source.** Lattimore and Hutter prove that no policy is strongly asymptotically optimal in the class of all deterministic computable environments: none converges to the optimal value in every environment of the class ([[11]](#r11), Theorem 8, part 1). The theorem's scope is its own: a policy is a deterministic map from histories to actions (Definition 3), action and observation sets are finite and rewards lie in [0, 1] (Assumption 2), and the discount function is computable with finite, positive tails (Definition 5). It concerns that class and that limit, not a finite horizon in a smaller class.
- **Acorn's theorems.** Over an interface with at least two actions, a kernel agent's first action is fixed by its initial memory and the first percept. So for every such interface, every percept and every kernel agent there is a world delivering that one percept at every state, with a start state and a goal of step cap one that some action sequence meets and the agent's closed loop does not (`no_agent_achieves_every_world`). The executed agent is such an agent over the grid interface, from every state of it (`executed_defeated`). This is a lemma for why the mission theorem has preconditions, not a result about learning.
- **Acorn's choice.** The contract quantifies over a stated class whose preconditions exclude such worlds, and the class grows step by step toward the mission. As the [README](../README.md#purpose-and-worlds) says, "each restriction is a step toward that end, not a narrowing of it".

### In a big world nobody does well on a first encounter

- **Source.** In the Alberta Plan, "The larger sensory signal, the observation, is explicitly not expected to provide complete information about the state of the environment" ([[3]](#r3), "Research Vision"), and in a big world the agent "can neither fully perceive the state of the world nor can it represent the value or optimal action for every state" ([[2]](#r2), "The Big World Hypothesis"). Partial observation alone does not make a first encounter fail: a fixed rule still solves a goal whose solution its observation shows.
- **Acorn's theorems.** A class *conceals* its goals when every member shows the agent the percepts of one reference world until that member's goal is first met (`Conceals`). In such a class every agent, learning or not, solves on a first encounter at most as many members as one action sequence meets (`Conceals.need`). In the grid world this covers the executed agent: from every state of it, it solves at most 49 + 7·cap of the concealed targets on a first visit of cap steps (`executed_find_first`).
- **Acorn's choice.** The promise is improvement from experience, never success on a first try, and concealment is a precondition of a big class ([contract 2](#contract-2-what-makes-a-class-of-worlds-big) (b)).

## Contract 1: the interface every world meets

**The owner-confirmed restatement.**

1. Each step, the world sends the agent an observation and a scalar reward, and the agent answers with one of the actions the world makes available. **[research]**
   - Source: the Alberta Plan names observation, action and a scalar reward as the agent's three signals (Sutton, Bowling and Pilarski, [The Alberta Plan for AI Research](https://arxiv.org/abs/2208.11173v3), "Research Vision", PDF pp. 1–2 and Figure 1); an observation is information about the state of the world that is "potentially incomplete" (Sutton, [The Quest for a Common Model of the Intelligent Decision Maker](https://arxiv.org/abs/2202.13252v3), §2, PDF p. 2); and the environment specifies within its definition the interface to the agent, the actions available to it included (Silver, Singh, Precup and Sutton, "Reward is enough", §2.3, PDF p. 4, read in the [co-author's open copy](https://web.eecs.umich.edu/~baveja/Papers/RewardIsEnough.pdf) of the article at [doi:10.1016/j.artint.2021.103535](https://doi.org/10.1016/j.artint.2021.103535)).
2. The set of actions is fixed in advance for each world. **[Acorn's choice]**
3. Any further signal a world provides, such as a task signal, is part of the observation. **[Acorn's choice]**
4. The observation need not reveal the world's state, and the world generates the reward outside the agent's direct control. **[research]**
   - Source: the observation "is explicitly not expected to provide complete information about the state of the environment" ([The Alberta Plan](https://arxiv.org/abs/2208.11173v3), "Research Vision", PDF p. 2), and observations are "potentially incomplete" ([Quest](https://arxiv.org/abs/2202.13252v3), §2, PDF p. 2); the agent's goal is "a scalar signal generated outside the agent's direct control" ([Quest](https://arxiv.org/abs/2202.13252v3), §4, PDF p. 3), and at AGI-25 Sutton places the reward's computation outside the agent because "the agent is not allowed to uh just set its reward to be high" ([the OaK keynote at 7:20:13](https://www.youtube.com/watch?v=XqYTQfQeMrE&t=26413s)).
5. Everything the agent learns comes from these signals, never from the world's internal variables. **[research]**
   - Source: "We expect all learning to be grounded in these three signals and not in variables internal to the environment", the setting the Alberta Plan chooses, which it sets against "special training sets, human assistance, or access to the internal structure of the world" ([The Alberta Plan](https://arxiv.org/abs/2208.11173v3), "Research Vision", PDF p. 2).
6. No host, viewer or tool writes what the agent learns or decides; the viewer can only stop it. **[Acorn's choice]**
7. A world may restart, between attempts or by its own rules, as part of its own dynamics, and a restart may be the agent's own action, as ARC-AGI-3's RESET is; the agent never restarts, and its memory is never reset. **[the owner's decision, F3, reworded under fork F-C]**
8. Every world Acorn runs (the tile world, each ARC-AGI-3 game and the Microduck) meets this one interface. **[Acorn's choice]**

The design below the contract:

- **Source.** "These three time series—observation, action, and reward—constitute the experience of the agent. We expect all learning to be grounded in these three signals and not in variables internal to the environment" ([[3]](#r3), "Research Vision", Figure 1). The reward "is scalar and defines the ultimate goal of the agent—to maximize the total reward summed over time" (same passage), and the reward hypothesis states "That all of what we mean by goals and purposes can be well thought of as maximization of the expected value of the cumulative sum of a received scalar signal (reward)" [[4]](#r4).
- **Acorn's choice and theorems.**
  - By construction: a world is a `Kernel.World` over the executed `Interface`, and an agent a `Kernel.Agent` whose only input is a `Percept` (a frame and the reward word) and whose only output is an action below the interface's declared count. That no agent reads a world's state is a fact of the types, for every kernel agent. The executed decision is such an agent (`executedAgent`).
  - Further signals inside the observation (sentence 3): a world's declared signals, its subtask potentials and its flag that the last transition achieved the installed goal are fields of the frame (`Frame`), the observation, so they reach the agent only as part of it.
  - What the executed decision reads of a percept: on two percepts that agree in the frame's active features and unit outputs, the reward word and three declared extra arrows, it returns the same decision and the same next state (`act_extras`).
  - No host write reaches learning: a host operation that keeps the learners changes neither the next decision nor the learners after it (`act_accounting`), and from two states with the same learners the executed agent takes the same action at every time, in every world (`executed_actions`). At each of the three step orders, the agent's step from two states with the same learners returns the same decision and states with the same learners (`actOrdered_learners`), so it reads its lifetime observations only to write them; every order's step reaches the completion boundary, which writes them (`TemporalControl.finish_eq`).
  - The viewer: only a stop request enters the core, at an attempt boundary, and source and compiled ownership keep learned code from reaching host control ([verification](verification.md#viewer-ownership-boundaries)). This is enforced by gates, not by a theorem ([obligation 3](#open-obligations)).
  - Goals: Acorn states a goal as an attempt goal, a condition on states with a step cap, so that achieving it is an event a theorem can count over a class's members. The reward word remains the agent's signal, and under fork F-A, the owner's decision, reaching a member's goal reaches the agent as reward, with each class proving that its reward and its count of members solved order agents alike ([the postcondition](#the-postcondition-what-achieves-goals-promises), sentence 2). Counting attempt goals is Acorn's instrument for the proofs, not a consequence of the reward hypothesis.
  - Restarts (sentence 7) are [fork F3](#fork-f3-the-world-may-restart-the-agent-never-does).
  - Every world on one interface (sentence 8) is a requirement each world's adapter must meet, not yet a checked fact about the ARC-AGI-3 and Microduck worlds ([obligation 13](#open-obligations)).
  - The intent record of this contract, `AcornVerif.Intent.WorldInterface.worldInterface`, states sentences 1 to 7 as nine properties of every step a run takes, for a world, an agent and the run that couples them over types each world chooses, so that it speaks of the tile world, an ARC-AGI-3 game and the Microduck alike; sentence 8 is the record applied to each world Acorn runs, which the proof of the executing code ([#213](https://github.com/rbeauchamp/acorn/issues/213)) and obligation 13 state world by world. The record reads "its memory is never reset" as a property of the run: nothing a host, a viewer, a tool or a world's restart does resets the agent's memory or restarts the agent; that the agent itself keeps what it learned across attempts is sentence 4 of contract 3. Its confirmation file, `lean/AcornVerif/Intent/WorldInterface.md`, gives each consequence's status and how each difference from a second model's blind reading was settled.
- **Open.**
  - [Obligation 2](#open-obligations), the campaign join.
  - [Obligation 3](#open-obligations), the viewer's rule as a theorem.
  - [Obligation 13](#open-obligations), the classes of ARC-AGI-3 games and Microduck scenes, each over this interface.

## Contract 2: what makes a class of worlds big

This is fork F2: what measures "big".
The owner confirmed the restatement below as a whole on 2026-11-03; the sentences in it marked as Acorn's choice were decided on the owner's behalf.

**The owner-confirmed restatement.**

1. A world is big relative to an agent: the agent is far smaller than the world in the resources its task needs, so it can neither fully perceive the world's state nor represent the value or best action for every state. **[research]**
   - Source: "The big world hypothesis says that in many decision-making problems the agent is orders of magnitude smaller than the environment. It can neither fully perceive the state of the world nor can it represent the value or optimal action for every state." (Javed and Sutton, [The Big World Hypothesis and its Ramifications for Artificial Intelligence](https://oaklab.ai/posts/the-big-world-hypothesis), section "The Big World Hypothesis"). In 2026 Sutton draws the consequence for what the agent learns, under the slide title "The Big World Perspective: The world is much bigger and more complex than the agent": "nothing the agent learns can be exactly correct", and "Instead, everything must be approximate:", with the sub-bullets "value functions", "policies", "transition models" and "states" ([the OaK lecture at MIT CSAIL](https://www.youtube.com/watch?v=GfmE2NPSN50&t=826s), slide on screen at 13:47).
2. Bigness belongs to the pair, and a class can be made big by restricting the agent instead of enlarging the world. **[research]**
   - Source: the hypothesis "can be made true or false by exercising control over the design of the environment and the agent" ([Javed and Sutton](https://oaklab.ai/posts/the-big-world-hypothesis), section "The Big World Hypothesis"), and for benchmarks "The alternative is to restrict the computational capabilities of the agents instead of making the environments larger" (same work, section "Benchmarking Algorithms in Big Worlds").
3. A big world need not change by itself: a fixed world can appear to change to an agent that cannot represent a good solution everywhere, and when its experience is temporally coherent, continuing to learn can then do better than any fixed solution. **[research]**

**Acorn's choice: qualify learning separately from bigness.** The mission theorem is specialized to each chosen class, rather than claiming that this structure alone implies separation for Acorn's agent. Its additional premises are [obligation 4](#open-obligations), the goal-information and exploration premises.

*Argued obstruction.* Two members can give the same constant percept forever while requiring different first actions for their one-step goals. With len = k = 1, both goals are feasible, concealment holds, and one action sequence covers at most one member. Every agent nevertheless has identical memories and actions in the two runs, by induction on the shared percept stream, including across visits. It solves at most one member on any common visit. Thus (a) to (c) alone cannot support the mission implication.

The replay comparison has a precise additional premise: one function signal from percepts to booleans must, for every member i, state s and action a, return true on that member's percept after stepping from s by a if and only if that successor state satisfies member i's goal (`replay_separates`). The same function serves all members; it cannot be given the hidden member index. The theorem also requires a fixed exploration schedule whose visits up to some finite last visit meet the goals of a set of more than k members. Feasibility alone does not establish that a particular schedule does so. These hypotheses suffice for the replay agent's separation, not for Acorn's executed agent; the latter's corresponding goal-information and exploration premises are [obligation 4](#open-obligations). The grid-world theorem `witness_separation` discharges the replay hypotheses for its stated set of targets.

**Condition (d): a counting bound** (`campaign_count`, `campaign_count_bits`).
A *campaign* presents N ≥ 1 slots of a concealed class in one stream (`campaign`): one visit of a fixed length to each slot in turn, cycle after cycle, never restarting the agent, and each slot's world starting each visit from its own start state.
An *assignment* picks, for each slot, a member from a set of T members, so there are T^N assignments.
Let k be the class's covering bound for one visit.
Then for every agent, every N and every cycle, the assignments on which the agent solves every slot on that cycle (`SolvesSlot`) number at most m · k^N, where m is the size of any set holding the memories the agent has at that cycle's start under those assignments (`campaign_count`).
For an agent whose memory takes at most 2^b values (`MemoryWithin`, b bits), that is at most 2^b · k^N assignments (`campaign_count_bits`).
The fraction of such assignments is then at most 2^b · (k/T)^N, which is below 1 exactly when N · log₂(T/k) > b (*argued*, from the count).

*Proof.*
Group the assignments by the agent's memory at the start of the cycle; there are at most m groups.
Within a group that memory is fixed.
On slot 1's visit, concealment makes the percepts those of the reference world until success, so the actions before success are fixed by the memory, and slot 1 succeeds for at most k members.
For each such member the run through slot 1's visit is determined, so the memory at slot 2's visit is fixed, and slot 2 succeeds for at most k members; and so on through slot N.
So at most k^N assignments fall in each group. ∎

The bound counts memory values, in bits; it needs no entropy, so the nats of the capacity C above play no part in it.
It is a lemma the mission theorem on campaigns uses, not a result about learning. It holds of the executed agent as of every agent; applying it to Acorn's capacity depends on [obligation 6](#open-obligations), the reachable-memory bound.
What it means for Acorn's agent today (*argued*): at a visit length of 96 steps, k = 49 + 7 · 96 = 721; a window of radius 99 holds 198² tiles, of which at most 49 lie within three tiles of the start and are not members, so it holds at least 39,155 members, and each slot carries log₂(39155/721) ≈ 5.76 bits.
If the agent's memory were the 59.8 million bits of its learned parameters, the bound would bite only beyond about 10.4 million slots, each visited twice at 97 decisions a visit: about 2.0 × 10⁹ steps.
That is why (d) is the scaled target and not today's precondition.

## Contract 3: invariants of learning from one stream

**The owner-confirmed restatement.**

1. The agent consumes its one stream as each experience arrives, in order, and stores no experience to replay as training data. It may make several internal updates per step, keep eligibility traces and plan with a model it has learned. **[research]**
   - Source: "Our batch-size-one learning algorithms can learn directly from experience without storing or replaying data" (Oak Lab, [Mission](https://oaklab.ai/mission), "Our algorithms learn in real-time without storing or replaying data"); the Alberta Plan's "strong preference is to fully process events as they occur", with every component updated "using the most recent events together with short-term credit-assignment memories such as eligibility traces" ([The Alberta Plan](https://arxiv.org/abs/2208.11173v3), "Designing around a base agent", PDF p. 5), and its base agent plans with a learned model on every step (PDF p. 4); "we want streaming algorithms so that we will exclude things like replay buffers" (Sutton, [the OaK keynote at AGI-25, 6:29:15](https://www.youtube.com/watch?v=XqYTQfQeMrE&t=23355s)); and "The agent streams the experiential data (never saves it)" ([the OaK talk at RLC 2025](https://www.youtube.com/watch?v=gEbbGyNkR2U&t=1315s), slide on screen from 21:55 to 22:56). In 2026 Javed names the single stream as the common case for continual learning: "Most use cases you have a single stream of data" ([Sequoia Capital's interview with Sutton and Javed](https://www.youtube.com/watch?v=xH7U7w9Qzlo&t=2390s), Javed at 39:50, caption text), and on planning with models: "The agents should learn from uh simulators, but simulators they make themselves" (same recording, Javed at 17:56, caption text). This is the discipline these sources choose, not a property of every algorithm their authors study, as the design below says.
2. Every step does bounded work and holds bounded memory, and the bounds do not grow as the run goes on. **[research in direction; the exact bounds are Acorn's choice]**
   - Source of the direction: an agent "has a fixed amount of computational resources throughout its lifetime, and there is no distinction between learning and deployment" (Javed, Shah, Sutton and White, [Scalable Real-Time Recurrent Learning Using Columnar-Constructive Networks](https://www.jmlr.org/papers/volume24/23-0367/23-0367.pdf), JMLR 24, 2023, §1, PDF p. 2), and "Computer power, though exponentially more plentiful, is never infinite" ([The Alberta Plan](https://arxiv.org/abs/2208.11173v3), PDF p. 3). In 2026 Sutton applies the cap to an agent's features: "you're just going to have to have a limit", "If you want to have more state features, you'll have to take out some less useful state features", and "the right way to handle the the the potential growth is to just cap it" ([the OaK lecture at MIT CSAIL](https://www.youtube.com/watch?v=GfmE2NPSN50&t=4049s), from 1:07:29, caption text).
3. There are no special training periods: on every step of its life the agent may learn, and may plan with a model it has learned. **[research]**
   - Source: "There are no special training periods when training information is available or when rewards are counted more or less than others" and "If the agent learns or plans, then it learns or plans on every time step" ([The Alberta Plan](https://arxiv.org/abs/2208.11173v3), "Research Vision", PDF p. 2), with planning by a learned model on every step (PDF p. 4); and OaK's design goal that the mind "should grow from runtime experience not from a special training phase" ([the OaK talk at RLC 2025, 5:01](https://www.youtube.com/watch?v=gEbbGyNkR2U&t=301s)).
4. The agent is never reset: its memory carries across every attempt, every stop and every resumption. **[the owner's decision, F3]**
5. A stopped agent resumes exactly where it stopped, and afterwards acts and learns as it would have without the stop, in a world that waited for it. **[Acorn's choice]**
6. These hold on every step of every run, with no exceptions. **[Acorn's choice; the Alberta Plan allows considered departures, and Acorn chooses not to]**

The design below the contract.
Acorn's exact bounds are fixed functions of the world's interface and the agent's configuration, so that a theorem can state them.
Everything the agent knows at any moment is a function of its starting state and the percepts it has received, each consumed in order as it arrives: nothing is replayed as training data, trained offline, written by a host or reset.
Where planning with a learned model ends and replaying stored experience begins is [obligation 7](#open-obligations).

- **Source.** Oak Lab's algorithms "learn directly from experience without storing or replaying data" ([[1]](#r1), "Our algorithms learn in real-time without storing or replaying data"). The Alberta Plan's temporal uniformity: "Temporal uniformity means that all times are the same with respect to the algorithms running on the agent. There are no special training periods when training information is available or when rewards are counted more or less than others. … If the agent learns or plans, then it learns or plans on every time step." The same passage acknowledges "that there may be situations in which it is preferable to depart from absolute temporal uniformity", and on computation, "Computer power, though exponentially more plentiful, is never infinite" ([[3]](#r3), "Research Vision").   - No host write reaches learning: `act_accounting`, under contract 1.
  - Bounded memory, for some states: for every state whose evaluator naturals each encode within their allowance, a save writes at most a fixed number of bytes (`snapshot_size_bound`).
  - Bounded work, for an accounting: the accounting of a step's first part is bounded for every agent state and percept (`choose_work`). It bounds the accounting of a costed twin; the twin's correspondence with the compiled code was observed in one build and is not proved ([design](design.md#the-work-of-the-first-part)).
  - The intent record of this contract, `AcornVerif.Intent.OneStream.oneStream`, states the six sentences as eight properties of a world, an agent and the run that couples them, refining contract 1's subject by what the agent reports of its own steps (each internal update, as a learning update with its training datum, a planning update, a reset or another update, and the work of the step) and of how it resumes after a stop. Every learning update learns from the experience its step was given; the work and the number of internal updates of every step, and the memories every run holds, stay within bounds fixed before the run; an agent that learns or plans on some step does so on every step; no step makes a reset, and each step keeps the memory the agent's own answer produced; after every stop the agent resumes with the memory it held. Each holds at every step of every run, with no domain hypothesis. That these reports describe what the executing agent does is what the fifth step of [#215](https://github.com/rbeauchamp/acorn/issues/215) proves, through [obligation 7](#open-obligations), executed work and the once-only, no-replay contract, and [obligation 6](#open-obligations), a bound on the memories the executed agent can reach. ## The postcondition: what "achieves goals" promises

This is fork F1: how strong "achieves goals" is.
The owner settled it on 2026-11-03 by confirming the restatement below as a fourth contract and deciding forks F-A and F-B ([the confirmation](#the-owners-confirmation-of-2026-11-03)).

**The owner-confirmed restatement.**

1. What the agent pursues is reward, the world's scalar signal. **[research]**
   - Source: "That all of what we mean by goals and purposes can be well thought of as maximization of the expected value of the cumulative sum of a received scalar signal (reward)." (Sutton, [The reward hypothesis](http://incompleteideas.net/rlai.cs.ualberta.ca/RLAI/rewardhypothesis.html)); and "The second sensory signal, the reward, is scalar and defines the ultimate goal of the agent—to maximize the total reward summed over time" ([The Alberta Plan](https://arxiv.org/abs/2208.11173v3), "Research Vision", PDF p. 2).
2. In every class Acorn proves, reaching a member's goal reaches the agent as reward. The class states its whole reward function, how reward is aggregated and how long attempts last, so that a lemma can show, for the agents compared (the learning agent and every agent that keeps nothing of its experience) and on the attempts counted, that one agent earns more reward than another exactly when it solves more members. A promise about reward and a promise about members solved are then the same statement, in both directions. **[the owner's decision, fork F-A]**
3. After experience in its one stream, the agent gains more reward per attempt across the class than any agent that keeps nothing of its experience could, which by sentence 2 means it solves more members per attempt. **[Acorn's choice and proof obligation]**
4. Once it has solved a problem, it keeps solving it while that problem stays the same; beyond its capacity it may give up what it no longer needs, but it keeps the ability to learn it again. **[research in direction; exact retention is stronger than the research requires and is Acorn's choice]**
   - Source of the direction: knowledge used rarely can be given up, "They might forgo knowledge that is not frequently used by the agent to make room for knowledge used more often" ([Javed and Sutton](https://oaklab.ai/posts/the-big-world-hypothesis), section "The Big World Hypothesis"); "Saying learning is continual is not the same as saying learning is permanent" (Javed's PhD thesis, [doi:10.7939/81765](https://doi.org/10.7939/81765), ch. 1, PDF p. 21); and "even if the agent forgets recurring information, the agent can do well if it can relearn that quickly when needed" ([Kumar et al.](https://arxiv.org/abs/2307.04345v2), §2.2, PDF p. 8). Keeping the ability to learn is a separate matter from remembering: the loss-of-plasticity paper's method, which maintains plasticity in its experiments, "does not tackle the forgetting problem" ([[8]](#r8), Extended discussion, PDF p. 14).
5. Success is measured as reward over the agent's stream. Acorn's first theorems prove that the advantage arrives eventually, and a bound on how long learning takes comes next. **[the owner's decision, fork F-B]**
6. Nothing is promised about optimal behaviour or about success on a first encounter. **[research, read as a stance]**
   - Source: in the big-world perspective, "optimality is impossible" (Sutton, [The Alberta Plan for AI Research, slides](http://incompleteideas.net/Talks/AlbertaPlan.pdf#page=5), 2022, slide 5), read as a stance, not a theorem for every class and resource bound. The limit on a first encounter rests on Acorn's own theorem that concealed goals defeat every agent on a first visit (`Conceals.need`, [above](#in-a-big-world-nobody-does-well-on-a-first-encounter)), not on a source.

Why sentence 2 needs both directions (*argued*): with only the direction from more reward to more members solved, an agent that solves more members could still earn the same reward as one that solves fewer, since a successful attempt earning rewards (1, 0) and an unsuccessful one earning (0, 1) have equal return. A proof of a goal-count advantage therefore cannot establish the reward promise without the converse, from more members solved to more reward.
A success reward alone does not make the counted goal the pursued one either: the agent maximizes its whole return, so the lemma needs the complete reward function, what is earned on failure and elsewhere included, its aggregation and the attempt lengths. That lemma, for each class, is [obligation 16](#open-obligations).

The design below the contract.
Under sentence 2, the theorems state the promise over attempt goals, the countable instrument, and each class's lemma carries it to reward.
On each class of the ladder below:

- (i) *separation:* after experience, there is one visit number and a finite set of more than k members such that the agent solves each of those members on that visit in its separate run; every frozen agent solves at most k members on any visit;
- (ii) *retention:* while the problem stays the same, once the agent has achieved a member's goal it keeps achieving it on later visits;
- (iii) on classes beyond its capacity (contract 2 (d)), where it cannot keep every solution at once, it keeps the ability to learn, so that it can learn again a solution it had to give up. The precise form of (iii) is [obligation 10](#open-obligations).

Separation allows members outside that successful set to remain unsolved; retention applies to every member whenever it is solved. These quantify over separate runs from the same agent initial memory, with continuity within each member's visits. A campaign that interleaves different members in one run needs postcondition (iii).
The contract does not promise success on a first encounter, eventual success in every member or the optimal action in every state.
Under fork F-B the first theorems promise the advantage eventually; a bound on how many failed visits learning takes is the next step ([obligation 11](#open-obligations)), toward lifetime reward over the stream as the target.

- **Source.**
  - *Goals as reward.* The sources call a goal stated as a world state to reach narrower than reward: "The goal-state formulation is sometimes adequate, but less general than additive rewards" ([[16]](#r16), §4, PDF p. 3). Under fork F-A the promise is stated in reward terms, and attempt goals stay the proofs' instrument. Bowling and colleagues give the conditions under which preferences over histories can be expressed by a Markov reward ([[25]](#r25), Theorem 4.1, under its Assumptions 1–4 and Axioms 1–5); that is a conditional representation theorem, not the per-class lemma of sentence 2.
  - *Learning time.* "The lifetime error captures not only the quality of the solution discovered by the agent at the end of learning but also how quickly the agent finds the solution" ([[19]](#r19), §3.1, PDF p. 35), and Javed's control problem measures performance by lifetime average reward over a lifetime fixed in advance (§3.1–3.2, PDF pp. 35–36). The infinite-horizon average reward ignores any fixed finite stretch of learning ([[7]](#r7), §6.3, PDF p. 44) but still counts a learning delay that recurs forever (§2.2, PDF p. 8). The research uses both measures and does not choose between them, which is why the staging was put to the owner as fork F-B.
  - *Tracking.* Tracking "can perform better than any converging algorithm on a stationary problem" ([[5]](#r5), Abstract, shown in Section 2), and "tracking methods may outperform converging methods, even in stationary domains" ([[6]](#r6), Section 2.4). "Learning things when they are needed and discarding them when they are not is sometimes called tracking", and "A key requirement for tracking to be effective is temporal coherence" ([[2]](#r2), "Online continual learning for achieving goals in big worlds").
  - *Forgetting that follows resources.* An agent without the resources to retain everything "can learn aspects that are important for decision-making at the current time and discard them when they are no longer" (same section). Like a CPU cache, "by retaining the right pieces of information and discarding the least useful ones, a small cache can have a high hit ratio" ([[2]](#r2), "Humans extensively rely on tracking in everyday life"). Kumar and colleagues' experiments indicate that "A performant agent can forget recurring information if it can relearn that information quickly relative to the duration of the information's utility" and that "When computation is constraining, forgetting can increase average reward" ([[7]](#r7), the permuted-MNIST experiments of Section 6.1, as summarized at the end of Section 6). These are experimental findings, not theorems.
  - *Keeping the ability to learn.* "Plasticity = the ability to learn" ([[9]](#r9), slide 4). Standard deep-learning methods "gradually lose plasticity in continual-learning settings until they learn no better than a shallow network", and "Plasticity is maintained indefinitely only by algorithms that continually inject diversity into the network" ([[8]](#r8), abstract). Dohare's PhD thesis supports a narrower reading of that second quotation. In its Ant problem, whose friction changes at the first episode boundary after 2 million time steps since the last change, PPO with L2 regularization and Adam with equal decay rates (β1 = β2 = 0.99), which reinitializes no unit and adds no noise to the weights (the L2 update is Eq. 2.6, PDF p. 26), "kept adapting and maintained a high level of performance as the friction kept changing" ([[28]](#r28), §7.5, PDF pp. 120–121, Figure 7.15). The thesis still concludes that algorithms "that continually inject randomness and variability into the network can enable artificial neural networks to learn forever" (PDF p. 125), and its PPO agents learn from stored batches of experience (PDF p. 29). These are empirical findings, not a guarantee of relearning.
  - What the sources do not establish: a guarantee that the agent keeps a solution after its first success, a bound on relearning from every memory it can reach, or a bound on failed attempts. These are Acorn's design obligations.
- **The owner's decision (fork F-B) and Acorn's design: separation and retention first, the attempt bound next.**
  - Separation alone is too weak (*argued*): an agent that succeeds once by luck in many members and never again meets it, and shows no learning. Retention rules that agent out.
  - Retention of every solution forever is too strong (*argued*, from `campaign_count_bits`): the counting bound holds for every cycle, so once N · log₂(T/k) > b, a b-bit agent that has solved every slot at least once and kept every solution would solve every slot in the next cycle, which happens for at most a fraction 2^b · (k/T)^N of the assignments. Keeping every solution would also contradict the tracking the sources describe, in which knowledge no longer used is given up.
  - Within one member's visits the problem is the same on every visit, because each visit starts the member's world from its start state; so there retention is required on every later visit, as the proposed form below states.
  - Separation and retention are jointly satisfiable and not trivially met: an agent that replays a route it has found re-solves on every later visit each member it solved once, wherever one common signal decodes goal satisfaction from the percept after every step (`replay_keeps`, `replay_solves`). With that same decoding hypothesis, concealment, a covering bound and an exploration schedule that meets the goals of more members than the bound by a finite visit, it separates (`replay_separates`); one grid world discharges these hypotheses (`witness_separation`). No frozen agent separates (`visits_need`). Retention alone is met by an agent that never succeeds; the conjunction is not. Replaying actions in the world is distinct from replaying stored experience for training, and these theorems prove neither the no-replay learning contract nor fixed resource bounds.
- **Open.**
  - [Obligation 9](#open-obligations), separation and retention for Acorn's executed agent.
  - [Obligation 10](#open-obligations), the precise form of (iii) for campaigns.
  - [Obligation 11](#open-obligations), the attempt bound.
  - [Obligation 16](#open-obligations), each class's reward lemma.

*Proposed* Lean form of (i) and (ii):

```lean
def Separates (family : WorldClass I) (goals : family.Goals) (len k : ℕ) (A : Kernel.Agent I) : Prop :=
  ∃ (visit : ℕ) (solved : Finset family.Index),
    k < solved.card ∧ ∀ i ∈ solved, SolvesOnVisit family goals len A visit i

def Retains (family : WorldClass I) (goals : family.Goals) (len : ℕ) (A : Kernel.Agent I) : Prop :=
  ∀ i visit later, visit < later →
    SolvesOnVisit family goals len A visit i → SolvesOnVisit family goals len A later i
```

## Fork F3: the world may restart; the agent never does

This is the owner's decision, which the owner kept on 2026-11-03 under fork F-C with the rewording below ([the confirmation](#the-owners-confirmation-of-2026-11-03)).
The confirmed restatements state it as sentence 7 of [contract 1](#contract-1-the-interface-every-world-meets) and sentence 4 of [contract 3](#contract-3-invariants-of-learning-from-one-stream).

**In plain words.**
The agent is never reset: its memory carries across every visit, every stop and every resumption.
A world may restart, between visits or by its own rules, as part of its own dynamics, and a restart may be the agent's own action, as ARC-AGI-3's RESET is; the agent never restarts, and its memory is never reset.
Each restart is part of the class's declared dynamics.
A class of worlds with no restarts at all, the continuing setting the research prefers, joins [the ladder](#the-mission-theorem-and-its-ladder) later.

- **Source.** Sutton's preferred setting is continuing: "there are no episodes, no discounting" ([[21]](#r21), slide 5). A general environment nevertheless "may terminate and reset to an initial state" ([[17]](#r17), Table 1, PDF p. 4), and the Physical Atari agent goes on learning while its Atari games end and restart, scored by "the average reward over all past experience" ([[24]](#r24), §4, PDF p. 8). In Sutton and colleagues' reward-respecting subtasks, the agent interacts with its environment "in a sequence of episodes", each beginning in one fixed start state, and "termination resets the state", while the policy the agent follows "gradually approaches an optimal policy" ([[10]](#r10), Section 2). So this work on options and planning sets its subtasks in a world that restarts under a learner that continues across episodes. The Alberta Plan's agents are "long-lived" and, if they learn, learn "on every time step" ([[3]](#r3), introduction and "Research Vision"). No source states that the agent is never reset; that rule is the owner's decision.
- **Acorn's argument and theorems.**
  - A world that persists between attempts can hold what the agent's memory does not. An agent that follows a step counter until its percept shows the goal met, and then takes an action that keeps it met, keeps every goal it has met although its memory reads no percept (`park_keeps`). In such a world no frozen-agent bound on later visits follows, and a learner that beats the first-visit bound shows nothing a frozen agent could not.
  - Visits restart the world and not the agent: each member returns to its own start state between visits, so on every visit every frozen agent solves at most the covering bound (`visits_need`), while the learning agent's memory carries over.
  - ARC-AGI-3 games restart: RESET "Initializes or restarts the game or level state", and in a game-over state it is the only valid action ([[14]](#r14), "Actions"). A contract that forbade the world to restart would exclude these worlds.
  - In ARC-AGI-3 every restart is the agent's own action: RESET is one of the actions the agent sends, forced after a game over and otherwise its choice. On a game already started, "If at least one ACTION command has been issued since the last level transition, only the current level is restarted", and "If no ACTIONs have been issued, the entire game resets" ([[15]](#r15)). Hence the wording kept under fork F-C: a world's restart can be the agent's own action, and it restarts the game or its level, never the agent's memory.
  - A stop does not reset the agent: resumption restores the saved state exactly (`load_saved`).
  - The host runs visits ([design](design.md#runs-of-visits-in-the-host)): `Host.runVisitDecisions` holds one start, returns the world to it after every visit and keeps the agent. For every construction, at every step order, from every state of it, after any number of decisions a run reached, the kernel's world in visits holds the run's world, carried result and step count, the kernel's memory and the run's agent have the same learners, and the action of a next decision that observes successfully decodes the kernel's action at that time (`executed_visits_closed_loop`).
  - On a member of the class of concealed targets, a run has completed one visit for every cap + 1 decisions, rounded down, and reports a completed visit solved exactly when the kernel's agent solves that member on it (`executed_visits_solved`). A value the native loop returned, unless it is a refusal, holds that run after some number of decisions within its budget (`runVisitDecisions_complete`). So for one visit index, fixed for all members, such values report at most 49 + 7 · cap members solved first on that visit, for one state of a construction (`executed_runs_first_success`), and at most 49 + 7 · cap members solved on that visit, for one stream of the uniform-random comparator (`comparator_runs_need`). Nothing bounds the members solved first at a visit each chooses for itself: a learner that solves more with experience is what the mission wants. Nothing says the loop returns, and no theorem ties the native entry `acorn-core visits` to the loop.
  - A crash is a loop that did not return. The loop writes a checkpoint only at a visit's boundary, so a crash leaves the last completed save or none. From a visit's first state, the agent resumed from the bytes a save at a boundary wrote has the states, the actions and the learners of the original kernel run from that boundary, at every later time (`visits_resumed`). So the visit a crash interrupted runs again exactly and no learning is lost. The rest of the agent is not claimed: resuming starts a new session, so its evaluator's session statistics and pending records restart, and the host's report, action fingerprint and checkpoint schedule are not saved. The theorem does not say that the bytes loaded are the bytes this run saved or that the later process was given the same start and cap; both are assumed, as is that a completed save survives the crash and a partial one leaves the old file. `lean/Acorn/Host/Checkpoint/IO.lean` states what a saved report establishes on each platform; where a sync stops at the drive, a power loss can lose this save and the image it replaced.
- **Open.**
  - [Obligation 14](#open-obligations), a world that restarts in the middle of a visit.

## Fork F4: how guarantees for exploring agents are stated

This was decided on the owner's behalf.

**In plain words.**
A guarantee about an agent that explores with its random generator may be stated as holding on all but a stated fraction of runs, under the explicit assumption that the generator's draws are ideal: independent and uniform.
That assumption is a hypothesis of each such theorem, never an axiom, and it is listed in the mission theorem's trusted base, together with the acknowledged gap between ideal draws and Acorn's actual generator.
Where a guarantee needs no randomness, it holds on every run.

- **Source.** Reinforcement-learning theory states guarantees for learning agents in probabilistic forms. Differential Q-learning converges "almost surely" if the MDP is communicating, the solution of its Bellman equation (Equation 5) is unique up to a constant, step sizes decrease appropriately, every state–action pair is updated infinitely often and the ratio of update frequencies stays finite ([[12]](#r12), Theorem 1, Section 2). UCRL2's regret bound holds "With probability of at least 1 − δ" in every finite MDP of finite diameter with random rewards in [0, 1] ([[13]](#r13), Theorem 2, Section 2). The probability is that of the random process the environment and the algorithm generate together ([[13]](#r13), Section 1); UCRL2 itself chooses each action deterministically from its optimistic policy ([[13]](#r13), Section 3), so there the probability comes from the MDP's random transitions and rewards. The sources do not say that an exploring agent must draw random numbers, nor how an ideal random draw relates to a concrete generator.
- **Acorn's choice: probability is a modelling option, not a requirement.**
  - Concealment does not force random exploration (*argued*): where a goal's solution is one of finitely many candidates and each visit can try one, an agent that tries a new candidate on each visit succeeds within as many visits as there are candidates, on every run. Acorn's separation theorem takes a deterministic schedule of exploration (`replay_separates`), and one grid world discharges it with fixed walks (`witness_separation`).
  - Where a guarantee does rest on the agent's draws, it is stated over the ideal model, with the fraction δ of failing runs given. The fraction of failing runs is chosen over an expected count because separation and retention are properties of one run: a bound on that fraction says how often a run fails, which an expectation does not.
  - The gap is explicit. Acorn's generator is deterministic: seeded word streams after SplitMix64 and xoshiro256** (`Acorn.Rng`). Acorn proves exact counting facts about it, such as how many 64-bit words its range selection maps to each value (`current_range_card`), and these give a distribution only under the hypothesis that the source word is uniform. That the generator's outputs may stand in for ideal draws is an acknowledged assumption of the trusted base, not a theorem.
  - This trades strength for a proof route: a guarantee under the ideal model is weaker than one counted exactly over the generator's 2^64 seeds. Every theorem that uses the model names its assumption, so the trade stays visible.
- **Open.** [Obligation 12](#open-obligations), a guarantee counted exactly over the generator's seeds.

## The mission theorem and its ladder

Put together, under F1 to F4, the mission is one theorem for each chosen class of a ladder of classes. The class, goals, visit length, covering bound and learning preconditions are fixed for that theorem; the conditions of `BigClass` alone are not sufficient premises.
For the executed agent from its initial state s₀, with work and size measures and bounds fixed by the interface and configuration, the proposed conclusion is the conjunction of:

- the resource bounds stated by the proposed StreamResourceBounds predicate;
- the separate once-only, no-replay contract, causal dependence, host isolation and exact resumption of contract 3, linked to the executed learning and lifecycle operations;
- separation as stated by the proposed Separates predicate for that class, carried to reward by the class's lemma ([obligation 16](#open-obligations)), as the owner decided under fork F-A;
- retention as stated by the proposed Retains predicate for that class.

Under fork F-B this conclusion is the first step of a staged promise: the advantage it states arrives eventually, a bound on how long learning takes is the next step ([obligation 11](#open-obligations)), and lifetime reward over the stream is the target.

Each class theorem must establish its bigness conditions and discharge [obligation 4](#open-obligations), the goal-information and exploration premises. The replay comparison uses exactly the decoding and exploration hypotheses described in contract 2. Neither the existence of feasible action sequences nor the comparison theorem supplies Acorn's learning justification.
Where the agent's exploration draws on its generator, F4 turns separation and retention into statements about all but a fraction δ of runs, under the hypothesis that the draws are ideal.
The replaying agent establishes joint satisfiability only of separation and retention under its hypotheses, and no frozen agent meets separation (see [the postcondition](#the-postcondition-what-achieves-goals-promises)). Satisfiability of the complete conjunction with fixed resources and the learning and lifecycle invariants remains open; discharging [obligation 9](#open-obligations), separation and retention for the executed agent, would establish it.
The full Lean theorem needs [obligation 7](#open-obligations), executed work and the once-only, no-replay contract; [obligation 4](#open-obligations), the goal-information and exploration premises; [obligation 15](#open-obligations), the failure fraction under F4; and [obligation 16](#open-obligations), each class's reward lemma.

**Proof boundary.** Refining this contract into Lean requires preserving each cited theorem's quantified domain, hypotheses and exact conclusion: a frozen-agent upper bound supplies no learner's lower bound, a causal fold supplies no learning-update count, and a class-level existential set supplies no guarantee for every member. This correspondence with the prose is argued, not machine-checked; the missing semantics and execution linkage remain proof obligations, not established guarantees.

The ladder starts with the concealed targets of one grid world. Its later rungs include campaigns beyond the agent's capacity (contract 2 (d)), classes of Microduck scenes, classes of ARC-AGI-3 games and, by the owner's decision under fork F-C, a class of worlds with no restarts at all, the continuing setting the research prefers; their order, like which world comes next, is not yet decided ([README](../README.md#purpose-and-worlds)).
"Any big world" is the limit of the ladder, never one theorem: each class is a step toward the mission, not a narrowing of it.

## Open obligations

Collected from the sections above, and stated only here: a section names an obligation by its number. An obligation keeps its number when it is discharged: number 1 was the finite form of "no agent achieves goals in every world", now `no_agent_achieves_every_world` and `executed_defeated`; number 4's class is `witness_big`, number 5's counting bound is `campaign_count`, and number 8's loop is `Host.runVisitDecisions`. Each of these is a lemma the mission theorem uses, not a mission result about learning.

2. That a whole campaign's run and the kernel's closed loops take the same actions, with the host's accounting composed along its attempts. What is proved is one attempt per boundary: for every construction, when a campaign boundary returns a next progress, the attempt it started reaches, in accepted passes within the step cap, an attempt whose close returns the next run state and writes only the attempt's accounting, and that attempt's own kernel closed loop holds the next run state's world and carried result, has its learners and takes each of its actions (`campaignStep_closed_loop`, `attempt_closed_loop`, `attempt_each_action`, [design](design.md#attempts-of-a-campaign-in-the-kernel)). A boundary that returned no next progress is outside it, and a refused action has only `Attempt.complete_learned`. What stays open: no theorem joins the boundaries, and the loop that repeats a boundary iterates over `Acorn.Host.forever`. Goal installation is not a kernel step, so a campaign is not one kernel loop and a joined statement cannot say that it is; the joined statement is a chain of kernel closed loops, one per attempt, with goal installation between them and one memory threading through. A run of visits has its own theorem (`executed_visits_closed_loop`, under [fork F3](#fork-f3-the-world-may-restart-the-agent-never-does)). The mission theorem's [first rung](#the-mission-theorem-and-its-ladder), the concealed targets of one grid world, runs in visits and does not use the join. Goal-information and exploration premises for each chosen class, among them a class of the grid world that meets contract 2 (a) to (c), sufficient for Acorn's executed agent, and a proof that they support learning by that agent. The class must expose enough goal information and support the agent's exploration; these premises must be stated independently of the mission theorem's conclusions, including the promised success, and justified for that class, establishing how Acorn's executed agent uses the information and explores. Bigness alone does not supply them, and the replay theorem's decoding and exploration hypotheses cannot be dropped when it is used as a comparison.
5. The choice of the agent configuration the counting bound of contract 2 (d) is first instantiated for: one of restricted capacity, as Javed and Sutton recommend for benchmarks ([[2]](#r2), "Benchmarking Algorithms in Big Worlds"), or only the full configuration. 6. A bound on the memories the executed agent can reach, which contract 3 and contract 2 (d) both need. Contract 3 needs it as the statement that every state the executed agent can reach has evaluator naturals within their allowance, so that its memory is bounded on every run. Also a separate, formal once-only, no-replay contract over the executed learning operations: direct learning from an experience must consume that experience once, in stream order; stored past observation/action/reward samples must not be submitted again as training data. Retained learned state, including learned parameters, and model-based planning remain allowed and are distinct from resubmitting experience. The current kernel interface has no experience-consumption semantics with which to state that theorem, and the resource predicate and causal fold establish no such consumption rule.

Discharged: a host loop that runs visits is `Host.runVisitDecisions`, related to `Kernel.visits` by `executed_visits_closed_loop`, `executed_visits_solved` and `runVisitDecisions_complete`, and `visits_resumed` is the account of a crash under the assumptions [fork F3](#fork-f3-the-world-may-restart-the-agent-never-does) states. 10. A precise postcondition (iii) for campaigns: learning again what had to be given up, stating from which memories the agent must be able to learn again, and within how many visits.
11. An attempt bound: how many failed visits learning may take, as a function of the class. Under fork F-B it is the next step of the promise after the eventual advantage. It needs a theory of exploration for Acorn's setting.
12. A guarantee for exploring agents counted exactly over the generator's seeds, with no assumption; until then, the ideal-draw assumption stays in the trusted base. 13. The classes of ARC-AGI-3 games ([#71](https://github.com/rbeauchamp/acorn/issues/71)) and Microduck scenes ([#173](https://github.com/rbeauchamp/acorn/issues/173)) stated over the interface, with proved preconditions or, where a world's rules are external code, preconditions stated as named hypotheses.
14. A world that restarts in the middle of a visit while the agent keeps its memory is a restart the visits model of [fork F3](#fork-f3-the-world-may-restart-the-agent-never-does) does not cover. The host's loop of visits cannot produce one.
15. Under F4, how the fraction δ depends on the class and the number of visits must be made precise before the full Lean theorem can be stated.
16. For each class of the ladder, under fork F-A: its whole reward function, what is earned on failure and elsewhere included, how reward is aggregated and how long attempts last, and a lemma that, for the learning agent and every frozen agent and on the attempts counted, one agent earns more aggregated reward than another exactly when it solves more members. With it a promise about reward and a promise about members solved are the same statement, in both directions. A one-way lemma does not suffice ([the postcondition](#the-postcondition-what-achieves-goals-promises)), and the conditional representation theorem of [[25]](#r25) does not supply it.
