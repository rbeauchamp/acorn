# Roadmap

This page says what Acorn works on now, in what order, and why.
GitHub's issues are the record of each piece of work; this page is the order between them.
It was last set on 2026-11-15, and a change to the order changes this page in the same pull request.

## Terms

- The *mission theorem* is the theorem the [mission contract](mission-contract.md) asks for: that Acorn's agent, as running Lean code, achieves goals over a formally stated class of big worlds. It is one theorem for each class.
- A *rung* is one such class of worlds, with its theorem. The classes form a ladder, from the first and smallest toward "any big world". Each rung has one tracking issue, labelled rung.
- An *obligation* is a numbered item of the mission contract's [open obligations](mission-contract.md#open-obligations): a statement not yet precise, a theorem not yet proved or a choice not yet made.
- A *lane* is a kind of work. On a rung there are three: *state* (write a contract, a theorem or a premise exactly, in Lean), *discover* (find the algorithm for which the rung's theorem is true) and *prove* (prove a stated obligation of the executing code). Four more group the rest: *world*, *theory*, *community* and *upkeep*.
- A *parked* issue is not on the active rung. It stays open, and its last roadmap comment says when it re-enters.
- A *mission*, as a unit of work, is an issue with a frozen contract that outside contributors and their agents can land ([missions](missions.md)).

## Where the mission stands

No theorem in the tree yet says that Acorn's executed agent acts better for what it has learned.
On the first rung, whose world, visit length and agent are fixed, `rung_mission` proves the mission theorem's statement from six premises about the executed agent. Two are proved: the one on memory, for the agent with its whole state as its memory (`rung_memory_bounded`), and the one on finding, that the agent solves more members than the covering bound, each on a visit of its own (`rung_finds`). Finding is a result about how the agent explores before any reward, not about what it learns from one. No theorem proves the other four, retention among them, and which memory the statement reads is the owner's decision ([#249](https://github.com/rbeauchamp/acorn/issues/249)). What remains is those premises, a proof that the agent's reports to contract 3 describe its step, a statement for an agent that explores with random draws, and the link from the rung's run to the native entry.

- **Proved.** The kernel's model of worlds and agents. That no agent achieves goals in every world, and that on a class which conceals its goals every agent solves at most a covering bound of members on a first visit. One class of worlds that meets the mission contract's conditions (a) to (c) for a big class (`witness_big`). That every agent which keeps nothing of its experience solves at most a covering bound of members on every visit (`visits_need`). That a reference agent which replays a route it has found separates from those agents and retains what it solved, under its own hypotheses (`witness_separation`, `replay_keeps`). That the host's loop of visits is the kernel's (`executed_visits_closed_loop`). Exact resumption from a checkpoint, and that no host write reaches learning.
- **Proved of the mission theorem's statement.** The statement is one proposition over the four intent records (`Mission`), and on a class of worlds in visits it follows from named premises about the class and the agent (`visits_mission`). On the first rung's class every premise about the class holds, the reward lemma included (`find_mission`, `classReward_eq`). A reference agent of fixed memory meets the whole statement there, with every premise discharged (`witness_mission`).
- **Proved of the first rung's constants.** The rung's world is the standard configuration at seed 1 and side 64 with no deer and no food (`witness_standard`), started at the box's center (`witness_start`); a visit is seven steps; the agent is the cold agent the host constructs for the primitive research profile (`rungConstruction`). The class is big there (`witness_big`), with at least 147 members (`witness_mission`) and at most 392 (`rung_members`) against a covering bound of 98. Every frame of the rung's agent holds at most 1712 slots, so the credit horizon holds of it with no hypothesis on frames (`rung_frames`, `rung_weight_rests`), and on the controller's cold run a slot laid at most seven steps before a first reward has a weight the reward moves (`rung_reach`).
- **Proved of the executed agent's exploration.** Take a profile with no hierarchy (primitive actions only, with no options and no meta-controller) under the declared exploration rate (the fixed rate of [departure D6](learned-only-binding.md#d6--exploration-rate--step-9)), which the primitive research profile is. At the default step order, from cold initialization and up to the first reward word that is not zero, its agent takes the actions of an *explorer*: a machine whose whole state is the exploratory run it has committed to and the action generator, and which reads no percept (`cold_actions`, `Explorer.step_eq`). On a class that conceals its goals behind a *reference* (one world whose percepts every member shows until its goal is first met), an agent solves a member on some visit exactly when the actions of some visit of its run in the reference, taken in that member, meet the member's goal (`Conceals.found_iff`). In the first rung's reference no reward is ever paid (`reference_unpaid`). So whether the rung's agent finds is a property of one action sequence (`rung_finds_iff`), and Lean's kernel evaluates enough of it: the agent solves each of 102 members on one of its first 72 visits, against the covering bound of 98 (`rung_finds`).
- **Proved of the executed agent's controller.** Its control weights stay zero until its first reward (`pre_reward_weights_zero`). What a bias on a few slots then does to the greedy choice (`candidates_of_gap`, `candidates_of_resting`), and how far back a first reward reaches (`creditReach`). On the first rung, at a member's first success within the rung's agent's first 1000 decisions, the reward's credit is written at the start of that visit: right after the step that learns the reward, every slot of the frame the agent laid at the visit's first decision holds, in the row of the action taken there, a weight above the tie window, the margin within which the greedy choice treats two values as tied (`rung_credit`). That step writes each row's traces into its weights, and the agent's next action is one decision of primitive control over the totals of those traces on the frame it reads (`rung_weights`, `rung_choice`); the traces were laid before the reward. No theorem says which action that is.
- **Observed.** Two registered studies on the standard curriculum, each refuted at its horizon ([baseline assessment](baseline-assessment.md#conformance-sequence), U6 and U7). They describe the code before a later change to the hashes, and neither ran on the first rung's class.
- **Open.** The mission theorem, on every rung.

## The owner's direction

On 2026-11-05 the owner directed that all effort goes to Acorn's mission, with supporting work only for bugs, problems of velocity and issues already planned.
Under the mission contract, Acorn's results are theorems about running code; a run of the agent is a smoke test and never evidence.
The order below follows both: one rung is active, and work that no active rung needs is parked.

## The active rung: concealed targets in visits

The first rung is the class of concealed targets of one grid world, run in visits ([#230](https://github.com/rbeauchamp/acorn/issues/230)).
A *concealed target* is a goal whose location the agent's observation does not show until the agent reaches it.
A *visit* is one attempt of a fixed length, after which the world returns to its start and the agent keeps its memory.
The rung's theorem says that the executed agent solves more members of the class on one common visit than any agent that keeps nothing of its experience can on any visit, that it keeps solving what it has solved, and that it does both within fixed work and memory while learning from each experience once.

The replaying reference agent already separates and retains on this class, under its own hypotheses (`witness_separation`, `replay_keeps`), and a reference agent of fixed memory that remembers which of its exploring walks met the goal meets the rung's whole statement (`witness_mission`).
So the statement alone does not tell a continual learner from an agent built to memorise a route in this world.
The rung's value is that Acorn's general agent, with nothing specific to this world, meets it within the contract's invariants.
The first rung on which no agent can keep every solution is capacity, condition (d) of the mission contract.

### The rung's constants

The owner decided on 2026-11-14 that the first rung's world is the host's standard configuration at seed 1 and side 64 with no deer and no food, started at the box's center, with visits of seven steps and the primitive research profile (`rung_mission`).
The same class in the host's own world, deer included, is a later rung ([#256](https://github.com/rbeauchamp/acorn/issues/256)).

- **Why this world and visit length.** They are the one world and visit length at which a class is proved big (`witness_big`), in the one kind of world whose frames are proved within the sizes the credit horizon assumes (`rung_frames`). No theorem says a shorter visit fails.
- **Why seed 1.** It is the least seed at which the host's own world started at the box's center: Lean's interpreter evaluated the host's generation at side 64 to a start at the tile (27, 27) for seed 0 and at the center, (32, 32), for seed 1 (observed on 2026-11-14; not proved). So the rung's world has the start and the terrain of the world that `acorn-core visits` builds at seed 1 and side 64, and differs from it by that world's eight deer.
- **What a run of the entry would show.** In the same evaluation at seed 1, over seven steps with the body waiting, no food appeared, one deer stayed nine tiles from the start and the other seven at least 18 tiles from it, and walks of seven steps were open in all four directions (observed on 2026-11-14). A frame's window reaches five tiles, so that deer is in view only from tiles within five of it, which a walk reaches after at least four steps toward it, and no deer reads the body's action (*argued*). A run of the entry at that seed and side with seven steps is then a smoke test of a member, and differs from the member's run only where that deer is in view. No theorem relates the two worlds, and such a run needs the owner's authorization as any other does ([#232](https://github.com/rbeauchamp/acorn/issues/232)).
- **What was weighed.** A visit at the proved reach of a first reward, 81 steps, has a covering bound of 616, so its class needs the terrain of at least 89 tiles proved (*argued*: a step brings at most seven more targets within reach), against the 21 the witness reads. The host's own world needs three things proved first: that its spawn search ends at the box's center, a bound on the frames of a visit in a world with deer, of which only the interface's bound of 3648 slots is proved, and the walks in that world. The spawn search evaluates the terrain 163 times for each candidate it considers (`considerSpawn`). Lean's kernel took 0.66 seconds to classify the terrain of the tile (33, 32) of the rung's world, and 5.3 seconds, 0.75 seconds a step, to check the witness's walk of seven steps east (observed on 2026-11-14 in the cloud container of the session that fixed the constants, with Lean 4.35.0, as the profiler's type-checking time of a proof that the kernel decides). A proof pays the kernel's time for each tile it reads, each time its module is rebuilt.
- **What the agent's profile leaves out.** The primitive profile is one the host neither saves nor loads, so exact resumption says nothing of the rung's agent.

### What the rung's agent finds

The owner decided on 2026-11-15 that the rung's premise on finding is certified by Lean's kernel, at the cost recorded here (`rung_finds`).

- **What is proved.** The rung's agent solves each of 102 listed members on one of its first 72 visits: each lies within three tiles of the body's walk on visit 45, 47, 53 or 71, counted from zero (`rungWalks`, `rungFound`). It is proved of the agent's one run, with no assumption on the generator's words. Up to a first reward the agent's actions are the explorer's (`cold_actions`), no reward is paid in the reference (`reference_unpaid`), and a member is solved by a visit exactly when the run in the reference has met it by that visit (`Conceals.found_within`, `cold_found_within`).
- **What was observed first.** Lean's interpreter evaluated the explorer of seed 1 over the grid's nine actions, and the executed world step from the rung's world along its walks. The walks of the first 54 visits met 99 members, the first count above 98, and those of the first 400 visits met 155 (observed on 2026-11-15 in the cloud container of the session that proved the reduction, with Lean 4.35.0; about four seconds; not proved). No agent ran and no learner was updated: the evaluation read the generator, the draw of a policy whose values are all zero, and the world.
- **Why these four visits.** They are not the first at which the count passes the bound. A search over that evaluation chose them for their few moves, 18 in their 28 steps: taking every move to succeed, no choice of at most five of the first 72 visits that meets 99 members had fewer (observed, by a script outside the tree; no theorem says the choice is the cheapest). The kernel checks the walks themselves.
- **What the proof costs.** Lean's kernel took 5.2 seconds to evaluate the explorer's first 576 decisions (`rung_actions`) and 18.5 seconds to evaluate the world step along the four walks (`walks_traced`); the module took 28 seconds to build (observed on 2026-11-15 in the same container, as the profiler's type-checking time and the build's report). The kernel pays that time each time the module is rebuilt. The module's tables are data: a change to the generator, to the persistent draw, to the world step or to the terrain makes the evaluation fail, and the tables are then computed again from the definitions. Exploring without reward ([#170](https://github.com/rbeauchamp/acorn/issues/170)) would be such a change.
- **What it leaves open.** What the agent does after a first reward, which questions 2 to 4 of [#232](https://github.com/rbeauchamp/acorn/issues/232) ask; the next two sections answer the second for an early first success and say what the first decision after it reads. For another seed or another world the reduction to the explorer's walks holds (`cold_finds_iff`) and no walk is evaluated; for a profile with a hierarchy nothing is proved.

### Whether a first reward's credit reaches the start

This is question 2 of [#232](https://github.com/rbeauchamp/acorn/issues/232): after a first success in a member, does credit reach the start of the next visit. Its test is predicate i′ of [a comment on #140](https://github.com/rbeauchamp/acorn/issues/140#issuecomment-6537838112), which reads the credit where the reward writes it and nothing of the next visit. The *own credit* of the successful visit's start frame is what that visit's first decision laid on the frame's slots, as the reward finds it: with |φ₀| slots, step size α, trace total t₀ before the laying and the reward L steps later, α·|φ₀|·(1 − t₀)·decay^(L−1). At or below the *tie window*, the margin within which the greedy choice treats two values as tied, credit has not reached the start.

- **What is proved.** In the visits of a member, let the rung's agent meet the member's target for the first time at a step of a visit, within its first 1000 decisions. Right after the agent's step on the percept that carries that reward, every slot of the frame laid at the visit's first decision holds, in the row of the action taken there, a weight of at least a named word (`lowChain`): a lower bound on the trace a step lays on a frame of at most 1900 slots (the rung's frames hold at most 1712), decayed once for each later step before the reward. That word is above the tie window (`rung_credit`). Every member the agent solves on one of its first 125 visits has such a first success (`rung_first_credit`), and so has each of the 102 members of `rung_finds`, within the first 72 visits (`rung_found_credit`).
- **How that answers the test.** The word bounds from below what the first decision's own laying puts on each slot, and the weight is at least that. So each slot's share of the frame's own credit is above the tie window by itself (*argued*: the bound on the laid increment is a step of `laid_lower`'s proof and no theorem states it alone, or states the own credit as an executed word). Of the frame, this is proved: it holds a slot (`rung_frame_slot`), and right after that step the value of the action taken at the visit's first decision, at the frame laid there, is above the tie window (`rung_start_value`). That value is the row's whole total on the frame, of which the own credit is a part.
- **Why only the first 1000 decisions.** The agent's feature bank holds generated units, each with a slot of its own. Its *tester* replaces the least useful units at a fixed rate, and only units more than 1000 steps old; a replaced unit's slot is *retired*, which clears every learner's weight and trace on it. Through the agent's first 1000 decisions no unit is that old, so no slot is retired between the laying step and the reward (`young_ineligible`, `idle_test`, `young_step`). After that, a slot of the start frame that coincides with a retired one loses its credit; nothing is proved there.
- **What it does not say.**
  - That the weight is still there when the next visit starts, except for a first success on the visit's seventh step: the state the theorem describes is then the one the next visit starts from. After an earlier step, the steps that remain in the visit form their errors from the weights this reward wrote and can lower it (*argued*). No question of #232 asks this; the test of question 2 reads the credit where it is written.
  - That the greedy choice at the next visit's start is the action the weight was written for. The rows of later actions can hold more credit on the slots their frames share with the start frame, and the next start frame can differ from this one where the agent's own predictions are fed back (*argued*). Questions 3 and 4 ask what the greedy choice then does.
- **What follows for the scoped changes.** The one-step model of [#171](https://github.com/rbeauchamp/acorn/issues/171) is gated on a no to this question. Nothing proved gives that no: every first success within the agent's first 1000 decisions passes the test on each slot its start frame holds, and the 102 members of `rung_finds` have their first success there. A first success after those decisions is not decided. So the gate is not met by what is proved, and it is not ruled out for a later first success.

### What the first decision after a first reward reads

This is the opening statement of question 3 of [#232](https://github.com/rbeauchamp/acorn/issues/232): after a first success, does the greedy choice away from the route repeat one action. It does not answer the question.

- **What is proved.** In the visits of a member, let the rung's agent meet the member's target for the first time at a step of a visit, within its first 1000 decisions. A *trace* is what a step lays on the slots of its frame, in the row of its action, and what every later step decays; before a first reward the weights are zero and the traces are not. Right after the agent's step on the percept that carries the reward, every row's weight on every slot reads the trace the row held there when that step began (`rung_weights`). So the value of each action at a frame is its row's *trace total* there, the sum of those traces over the frame's slots (`reward_values`), and the agent's next action is one decision of primitive control over the policy of those totals, from the explorer's state after that many decisions (`rung_choice`, from `first_choice`). In such a decision a committed exploratory run with a step left serves its action; otherwise it is one persistent draw, which takes a near-maximum candidate of the totals unless the generator begins a run (`first_choice_greedy`). Every member the agent solves on one of its first 125 visits has such a first success (`rung_first_choice`), and so has each of the 102 members of `rung_finds` (`rung_found_choice`).
- **What the totals say.** The traces were laid before the reward, by steps that are the explorer's, and no trace reads a reward. So a total records which actions the agent took before the reward, how long before, and on frames that share how many slots with the frame the decision reads; it records nothing of where the reward was earned. Two things are proved of it in every world of the agent's interface, over frames of at most 1900 slots and before a unit of the feature bank matures. An action that the 119 steps before the reward took on no frame holding a slot of the decision's frame has a zero total, and is no candidate once that frame shares a slot with a frame laid at most nine steps before the reward (`unlaid_excluded`). And where every one of those steps whose frame holds a slot of the decision's frame took one action, that action is the one candidate (`sole_candidate`). Two frames whose percepts carry a common word share a slot (`shared_slot`).
- **What that means on the rung.** Little beyond the first visits. From its 39th decision to its 576th the explorer has taken every one of the nine actions on the 119 decisions before (`rung_taken`), so at a first reward at one of those times no action is excluded for not having been taken. And every frame the host observes under a concealed target carries the task words of `taskWords`, so every two such frames share a slot and every action taken competes at every frame (*argued*: no theorem says that the host observes at the states of the run, so none names a word that two of its percepts carry).
- **What it does not decide.**
  - Which action the decision takes. Where the steps before the reward took several actions, the candidate is decided by comparing their rows' totals, and a total depends on how many slots the decision's frame shares with each earlier frame. No theorem evaluates a total of the rung's run, so none says which action is the candidate, or that there is only one.
  - Whether one action is repeated. That is a statement of the decisions after this one. After the first reward the errors of the agent's steps are not zero words, so each step moves every weight whose slot holds a trace, and nothing is proved of them.
  - Anything of a first success after the agent's first 1000 decisions, for the reason the section above gives.
- **What follows for the scoped changes.** Stage 2 of [#170](https://github.com/rbeauchamp/acorn/issues/170) is the repair if the greedy choice repeats one action, and that is not decided. What is proved is the mechanism at the first decision: the reward turns the traces into weights, so the choice follows the actions taken shortly before the reward on frames that share slots with the present one. Deciding the question on the rung needs the trace totals of its run, and they need its frames: the words of its percepts and the units they turn on. A frame's window has 121 tiles, and Lean's kernel took 0.66 seconds to classify one tile of the rung's world, so the kernel would take about 80 seconds to read the tiles of one frame, before its units (an *estimate* from that one observation; nothing was run for it).

### Order of work

1. **State.**
   - The intent record of the postcondition, steps 1 to 4 ([#219](https://github.com/rbeauchamp/acorn/issues/219)).
   - The intent record of contract 2, steps 1 to 4 ([#214](https://github.com/rbeauchamp/acorn/issues/214)).
   - The rung's theorem in Lean ([#231](https://github.com/rbeauchamp/acorn/issues/231)). In the tree: its definitions, a proof that a reference agent meets it (`witness_mission`), a proof of it for the executed agent from named premises, two of them proved on the first rung (`executed_mission`), so the way the theorem depends on its obligations is checked by Lean's kernel, and the rung's constants (`rung_mission`), with the theorems its world and visit length rest on. Remaining: the decisions listed below, and the blind second reading of the statement.
2. **Discover.** Decide the rung for the primitive research profile, by theorem ([#232](https://github.com/rbeauchamp/acorn/issues/232)): does its exploration find enough members, does credit reach the start of the next visit, does the first reward collapse exploration, and does shared weight send the agent off its route. The first is decided: the rung's agent finds (`rung_finds`). The second is decided by the issue's test, for a first success within the agent's first 1000 decisions: right after the step that learns the first reward, each slot of that visit's start frame holds, in the row of the action taken there, a weight above the tie window (`rung_credit`). The test reads the credit where it is written; whether the weight is still there at the next visit's first decision is not proved. Of the third, the first decision after the first reward is characterized: it is one decision of primitive control over the totals of the traces the agent's rows held when the reward came (`rung_choice`). Which action that is, and whether it is repeated, is not decided. The fourth is open. Two algorithm changes are scoped and open on those answers: exploring without reward and after the first reward ([#170](https://github.com/rbeauchamp/acorn/issues/170)), and a one-step model that carries a success back ([#171](https://github.com/rbeauchamp/acorn/issues/171)).
3. **Prove.** The invariants, stated over constructions so that an algorithm change does not reopen them: reachable memory (proved for worlds of the grid, `visits_memory_bounded`), work ([#90](https://github.com/rbeauchamp/acorn/issues/90)), once-only learning ([#233](https://github.com/rbeauchamp/acorn/issues/233)), and the executing code against the records of contracts 1 and 3 ([#213](https://github.com/rbeauchamp/acorn/issues/213), [#215](https://github.com/rbeauchamp/acorn/issues/215)).
4. **Assemble.** The rung's theorem for the primitive profile, then for the ranked profile ([#230](https://github.com/rbeauchamp/acorn/issues/230)).

Stating comes first because it is the cheapest step and it decides which of the others are needed.
Discovery decides whether the theorem is true; the proofs of step 3 assume it.

## How the issues encode this

- **Milestones.** [Rung 1: concealed targets in visits](https://github.com/rbeauchamp/acorn/milestone/1) holds the active rung. [Later rungs](https://github.com/rbeauchamp/acorn/milestone/2) holds what waits for it. [Open the roadmap](https://github.com/rbeauchamp/acorn/milestone/3) holds the work for outside contributors.
- **Labels.** One lane on each issue: `lane:state`, `lane:discover`, `lane:prove`, `lane:world`, `lane:theory`, `lane:community` or `lane:upkeep`. A tracking issue of a rung carries the label rung. An issue off the active rung carries the label parked. `needs-owner-decision` and `needs-statement` say what an issue waits on: the second marks work that needs an exact statement before it can be posted as a mission.
- **Sub-issues** group the parts of one deliverable under its tracking issue.
- **Blocked-by links** give the order between issues.

The issues that can be worked on now are the open issues of the first milestone that no open issue blocks.
