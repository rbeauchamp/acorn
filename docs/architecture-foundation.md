# Architectural foundation: 4-layer federation and always-on live upgrades

**Status:** Technical architecture and decision record derived from [the architectural intent](architectural-intent.md) against baseline commit 9aea3cb. Owner-confirmed directions live in [the architectural intent](architectural-intent.md); the design, package boundaries, compiler recipes, and governance mechanics below are delegated engineering choices designed to uphold those commitments and [the mission contract](mission-contract.md).

## 1. Purpose, scope, and authority boundary

Acorn's mission is to discover and implement algorithms that enable agents to achieve goals in big worlds, verified in Lean 4 from a single experience stream ([README](../README.md#purpose-and-worlds)). Two requirements established on 2026-11-21 govern this architectural foundation:

1. **Community swarm scale (100–1,000+ concurrent contributors):** Pointing hundreds or thousands of external human and AI-agent swarms at Acorn must produce compounding verified progress rather than merge storms on central registry files, single-cone 360-second verification timeouts, or a dead-code hairball inside the released agent.
2. **Always-on living operation and author-agnostic RSI:** The agent must operate as a fault-tolerant, never-pausing system supporting verified zero-downtime live upgrades across an arbitrarily long lifetime — starting with externally pushed verified releases and designed from day one so future recursive self-improvement (RSI) modules pass through the exact same immutable outer verification and upgrade gate.

Owner-confirmed commitments live in [architectural intent](architectural-intent.md). Everything below specifies the concrete engineering architecture, compiler guarantees, anti-gaming closures, operational supervision, and phased GitHub issue roadmap ([epic #321](https://github.com/rbeauchamp/acorn/issues/321)) implementing those commitments.

## 2. Codebase forensics at baseline 9aea3cb

Inspecting Acorn's 191,856-line codebase at commit 9aea3cb established where monolith pressure actually sits versus which modular seams already exist.

### 2.1 Artificial centralization vs. real coupling bottlenecks

1. **Decision registries (`lean/Acorn/Decisions.lean` and `lean/AcornVerif/Decisions.lean`):** `Acorn.Decisions` is 8,462 lines / 477 KB (512 theorems, 232 Regula decision registrations, 278 Regula executable contracts) and has **zero importers anywhere in the repository**. It is forced into a single file strictly by three literal module-name checks in `lean/lakefile.lean` (lines 117–119), `lean/AcornTools/Boundary/Audit.lean` (lines 111–113), and `lean/AcornTools/OwnershipAudit.lean` (lines 154–155). Sharding it into per-module leaf files is purely mechanical.
2. **Nine central merge-conflict files:** Adding or changing a learning mechanism today forces concurrent PRs onto up to nine shared files: `lean/Acorn/Decisions.lean`, `lean/AcornVerif/Decisions.lean`, `lean/Acorn/Cost.lean` (a closed 92-constructor `Site` enum at line 238), `lean/AcornTools/Native/Routes.lean` (334 C-mangled symbol call routes and 14 closure lists), `lean/AcornTools/Native/Resources.lean`, `lean/AcornTools/Ownership.lean` (386 anchors and 20 executables), `lean/AcornTools/Boundary/Departures.lean`, `lean/AcornTools/AxiomPins.lean` (4,239 lines), `lean/AcornVerif/Landings.lean`, and `lean/AcornVerif/Targets/LearnedStateAcorn.frame` (2,147 declaration hashes).
3. **Closed-enum research profiles and manual destructuring:** Acorn uses zero typeclasses for agent subsystem dispatch. `Host.Runner` and `Handcrafted.FeatureProfile` map closed research-profile enums across dependent type indices and inline branches inside 5,178 lines of `lean/Acorn/Handcrafted/` (`TemporalControl`, `StepParts`, `DrawFirst`, `AgentAlignment`, `AgentEpisodes`, `Agent`), manually pattern-matching 5-level nested tuples so Lean 4 reference-count-1 in-place array updates hold across `detachedUpdate` and `takeOut` (`lean/Acorn/FeatureConsumers.lean`).
4. **Single-cone 360 s build and Regula blast radius:** Under `scripts/verify.sh` and `scripts/regula.sh`, every module under `Acorn` and `AcornVerif` builds and replays inside one verification cone and one hard 360-second process-group deadline. Editing core files (`State`, `SwiftTd`, `Features`) dirties ~66% (126–133 of 196) of `AcornVerif`; editing `Handcrafted` control dirties ~32% (60–65 of 196). Earlier mechanism PAR-18 had to be retired partly because its proofs sat on the critical path of the build budget ([prior-art review](prior-art-review.md)).
5. **Baseline-pinning invalidation:** Acorn's first plugin experiment ([the learned-state frame](learned-state-frame.md)) demonstrated that allowing contributors to replace the agent's step broke ablation guarantees (revision 1), forcing revision 2 to pin the baseline agent by declaration hash (`lean/AcornVerif/Targets/LearnedStateAcorn.frame`) — meaning any baseline learner edit invalidates prior proofs against that baseline.

### 2.2 Modular and fault-tolerant seams already built

Acorn already contains strong organic foundations that this architecture builds directly upon:

- **Outer and host interfaces:** `Acorn.Features.Interface` (`lean/Acorn/Interface.lean`), `AcornVerif.Kernel.World`, `AcornVerif.Kernel.Agent` (`lean/AcornVerif/Kernel.lean`), `Acorn.Host.Attempt` callbacks, and `Acorn.Host.Microduck.Stepper` (`lean/Acorn/Host/Microduck/Loop.lean`) already make hosts polymorphic over agent state.
- **Subsystem parameterization and lenses:** `Acorn.Features.OptionModelOps` and `Acorn.Features.PlanBoundary` (`lean/Acorn/Temporal.lean`) already decouple option models and boundary planning signatures; `Acorn.Features.PackedLearner` hides per-learner configuration inside `Ensemble`; `Oak.View` and `Oak.Realizes` (`lean/AcornVerif/Oak.lean`) model lens-based planning extraction; and `AcornVerif.LearnedState.Mechanism` (`lean/AcornVerif/Targets/LearnedState.lean`) establishes a store-isolated sensor-word plugin slot.
- **Compositional serialization and always-on supervision primitives:** `Acorn.Checkpoint.Format` (`lean/Acorn/Host/Checkpoint/Format.lean`) provides exact algebraic format combinators (`Format.Exact`); `Acorn.Host.Forever.loopIO` (`lean/Acorn/Host/Forever.lean`) compiles Regula-safe infinite host loops to C tail calls; `Acorn.Pace.outcome` (`lean/Acorn/Timing.lean`) and `Acorn.Host.Microduck.Stage` (`lean/Acorn/Host/Microduck/Loop.lean`) separate real-time deadline holds from an explicit quiescent `Stage.ready` boundary; `Acorn.Host.Viewer.Supervision` and `Acorn.Host.Viewer.Lifecycle` track durable `Identity` separately from ephemeral process generations; and `lean/Acorn/Host/Checkpoint/IO.lean` enforces crash-safe atomic checkpoint writes synced to stable storage.

## 3. Architectural evaluation and primary-source foundations

Four candidate architectures were evaluated from first principles against Acorn's contracts, Lean v4.35.0 compiler behavior, OaK continual-learning coupling, always-on fault tolerance, and 100–1,000+ contributor concurrency:

| Criterion (100–1,000+ contributors) | Model A: Dynamic runtime plugin bus in Lean | Model B: Monorepo coarse plugins only | Model C: Whole-agent competition islands only | Model D (Adopted): 4-Layer Federation + Always-On Supervisor |
|---|---|---|---|---|
| **Lean kernel / Regula / FBIP compliance** | Fails (dynamic lookup, open axioms, closures break RC=1) | Passes | Passes | Passes (*module* opacity + parameterized specialization keeps RC=1) |
| **OaK cyclic feedback loops** | Fails (cycles forbidden or quadratic blowup) | Strong inside one fixed wiring | Strong per agent | Strongest (coarse A/G + RUSC seams inside baseline; free internals in novel agents) |
| **Genuine algorithmic discovery** | Blocked (trapped in runtime hooks) | Constrained (fixed FC-STOMP slots) | Unrestricted | Unrestricted (supports both surgical seam swaps and paradigm shifts) |
| **Compounding of discoveries** | Weak (shallow contracts) | High inside one wiring | Fails (isolated islands) | High (distillation into primitives + multi-axis synthesis missions) |
| **Merge contention & 360 s verification** | Catastrophic (shared registries + global cone) | Blows up (1 global cone + central files) | O(1) per candidate package | O(1) per candidate package (frozen contracts + sharded primitives + isolated candidates) |
| **Baseline cleanliness (Anti-Frankenstein)** | Worst (hook/flag accumulation) | Moderate (profile/flag creep) | High | Highest (one clean epochal baseline; replace-and-delete promotion; simplification missions) |
| **Always-on fault isolation & live upgrades** | Fails (shared process; no verified migration) | Requires restart | Requires restart | Native (OS-process isolation + quiescent symmetric-lens migration + canary rollback) |

### 3.1 Why a dynamic Cordis-style runtime bus is rejected inside OaK (and no separate framework repo upfront)

Direct inspection of Cordis's TypeScript core and its 92-page formalization (Shi, Zhang & Cui, *A Programming Paradigm for Spatiotemporal Composability*, arXiv:2608.25512), DeepSeek-Harness's architecture and 30+ vendored framework patches, and Lean v4.35.0's compiler/Regula constraints establishes why an in-process dynamic plugin bus is the wrong substrate for Acorn's continual-learning core:

1. **Collapse in pure static languages (arXiv:2608.25512 §1.1, Def. 23, §6.7):** Cordis solves live hot-loading inside a mutable JS/TS host process. In a pure, statically compiled language, temporal revertibility collapses to lexical derivation and reactive coeffects collapse to static module/record wiring.
2. **Incompatibility with Lean 4 kernel rules and RC=1 memory ownership:** Lean v4.35.0's runtime dynamic type carriers (*Dynamic*) rely on `unsafe` casts banned by Regula RG1006; open extensible families (Lake.Util.Family) rely on explicit axioms banned by Regula RG1001; elaboration hooks (*initialize*, macros, custom attributes) are banned by `AcornTools.Boundary.Audit`; and indirect closure calls destroy Lean 4's reference-count-1 in-place vector updates (Ullrich & de Moura, *Counting Immutable Beans*, IFL 2019), forcing linear copies per step.
3. **Hostile topology for OaK and fault isolation:** Cordis forbids dependency cycles (arXiv:2608.25512 §4.1, §6.5 — mutual interaction causes inactive fibers or quadratic integration bloat), breaks commutativity on ordered middleware waterfalls (§3.4.2), carries only nominal key identity without behavioral invariants (§6.6), and executes in a shared process heap — violating Armstrong's Erlang/OTP fault-isolation axiom (Armstrong PhD 2003, Ch. 2.3) that shared-memory plugins cannot contain faults or deadline overruns.
4. **No separate standalone composition framework repository upfront:** Building a generic Lean composition framework in a separate repository invites premature category-theoretic abstraction decoupled from Lean v4.35.0 FBIP and Regula rules. Instead, minimal unboxed composition structures (~300–600 LOC) live directly inside `acorn-contracts`, with an explicit **graduation trigger**: extract them into a standalone library only after at least two substantially distinct verified agent architectures stabilize them across at least two epochs and a second Regula-compatible project requires them.

### 3.2 Synthesis of primary literature adopted

- **RL modularity history and OaK epistemology:** RL framework history (TorchRL, ICLR 2024 cataloging nine unmaintained frameworks; RLlib's multi-class rewrite; Dopamine and CleanRL showing premature internal splits obscure coupled updates and block radical ideas) and Sutton, Bowling & Pilarski's *Alberta Plan* (arXiv:2208.11173v3, *"the dilemma of the parts and the whole"*) show that internal agent decompositions are research hypotheses, not settled APIs. DeepSeek-Harness contributes its **3-role capability seams** (interface, exclusive provider, consumer) and declarative **whole-row replacement**, realized statically in Lean.
- **Large-scale Lean swarm organization:** Prove2Me (Chen et al., arXiv:2608.28433v2) contributes immutable mission targets, blind specification read-backs, and **Campaigns** (competing independent entries proved against shared foundation definitions without merging competing approaches into one codebase). Tau Ceti contributes mandatory Lean 4 module-system opacity, empty root modules with directory globs (zero central file edits), pre-queue declaration-name collision checks, public artifact caches, strict file-size bounds, zero backwards-compatibility rules, and cross-family fail-fast review rubrics with human ownership restricted to specs, rubrics, and promotion gates.
- **Formal compositional verification:** CertiKOS (Gu et al., POPL 2015 / OSDI 2016) explains why shallow interfaces fail on shared state (matching Acorn's six composition failures F-A through F-F in [the baseline assessment](baseline-assessment.md)) and why coarse seams (5–6) beat micro-layering. CompCertM's RUSC (Song et al., POPL 2020) resolves mutually coupled loops via well-behavedness context invariants (Self(*R*) at ~14% proof overhead vs. ~146% for monolithic global invariants). Benveniste et al. (Inria RR-8147) supplies Assume-Guarantee contract algebra unifying functional, cost, memory, codec, and provenance viewpoints. Spivak (arXiv:2005.01894v2) and Hedges & Sakamoto (arXiv:2404.02688v2) model step-varying action spaces (*available_actions*) and bounded in-agent mode rewiring cleanly via polynomial functors (*Poly*).
- **Verified live upgrades and RSI:** Erlang/OTP (Armstrong 2003), Proteus (POPL 2005), Kitsune (OOPSLA 2012 — proving quiescent whole-program cutover has ~0% runtime overhead vs. +18% to +42% for function-level hot patching), VSTTE 2012 behavioral DSU (showing reachability alone permits silent state wipes), LionsOS (arXiv:2501.06234v2 — OS/PD isolation and microsecond policy swapping), and Symmetric Lenses (Hofmann, Pierce & Wagner, POPL 2011) yield Regime 2's cutover and rollback model. Schmidhuber (arXiv:cs/0309048v5), Yudkowsky & Herreshoff (2013), Fallenstein & Soares (2015), and Everitt et al. (arXiv:1605.03142) ground the immutable outer trust boundary and object-level Löb-safe upgrade gating.

## 4. Regime 1: 4-Layer Federated Proof-Carrying Architecture

### 4.1 Package and seam topology

- **Layer 0 — `acorn-contracts` and `acorn-worlds` (Frozen, human-owned, version-pinned):**
  - Physically split `acorn-contracts-exec` (zero FloatLib, Mathlib, or `lean-intent` package dependencies — enforcing isolation in Lake itself) from `acorn-contracts-verif` (owning `FloatLibBridge` and `LeanIntentBridge`), alongside `acorn-worlds` (Grid, ARC-AGI-3, Microduck adapters).
  - Houses *Poly*-shaped `Kernel.World` / `Kernel.Agent` interfaces (supporting step-varying action availability), Contracts 1–4 `lean-intent` records, frozen rung `AcornVerif.Targets`, `LearnedState`-style attribution frames, and the minimal composition primitives: site-polymorphic `Costed`, *ExactCodec* (`Format.Exact`), stateful component contracts, A/G + RUSC composition laws, and symmetric-lens *VerifiedUpgrade* contracts.
- **Layer 1 — `acorn-primitives` (Reusable verified building blocks):**
  - Standalone *module*-opaque implementations (`SwiftTd`, tile coder, `FeatureLifecycle`, option models, `Planning`, `Exploration`, checkpoint format combinators) compiled with empty root module, Lake globs, per-module `*.Decisions` leaves, pre-queue header collision detection, file-size limits, and 5-artifact caching.
- **Layer 2 — Federated candidate Lake packages (100–1,000+ contributor surface):**
  - External humans and AI swarms build isolated packages pinned to `acorn-contracts` (and optionally `acorn-primitives` and `acorn-baseline`), running independent 360-second verification and Regula replay at the contributor's edge (`O(1)` blast radius per swarm).
  - **Track A (Coarse-seam upgrades):** Replace one coarse component inside the versioned baseline and prove local A/G + RUSC contract refinement, inheriting global work, memory, codec, and provenance guarantees.
  - **Track B (Whole-agent discovery campaigns):** Implement a completely novel `Kernel.Agent` (such as continual neural networks, option keyboards, or unified state-option learners) directly against Layer 0 contracts without fitting legacy slots.
  - **Distillation and synthesis consolidation:** To prevent Layer 2 from fragmenting into incompatible islands, winning Track B mechanisms require a `mission:distill` extraction into Layer 1 primitives behind an implementation-independent contract, and a public multi-axis Pareto Frontier triggers `mission:synthesize` missions to compose complementary frontier wins into dominating successors, alongside Simplification Missions that reduce baseline code or departures without regression.
- **Layer 3 — `acorn-baseline` (One clean epochal reference agent):**
  - Ships ONE minimal verified reference composition per epoch, wired across **5–6 honest coarse mathematical seams** established by codebase forensics (`lean/Acorn/FeatureConsumers.lean`, `lean/Acorn/FeatureLifecycle.lean`, `lean/Acorn/FeatureRefresh.lean`, `lean/AcornVerif/CurrentRetirement.lean`):
    1. *StateMechanism:* Isolated sensor-word extension seat (integrating `#320`).
    2. *FeatureSystem* ↔ *ConsumerEnsemble:* Cleanly separated behind a deep A/G + RUSC consumer contract exposing outgoing weight readout (*outgoing*), held-unit locks (*holds*), atomic slot retirement, unit release, observational equivalence, and search-control cleanup. Crucially, Demon-0 ranking, skill interest slots, ranked expectation models, meta-controller rows, model cache, and `Closing.oldOwner` detachment **must stay fused inside ConsumerEnsemble** because splitting them across opaque boundaries breaks shared rank/owner invariants and RC=1 in-place updates.
    3. *Planner:* Already proved realizable as an exact `Oak.View` lens.
    4. *Explorer:* Persistent exploration generator/policy seam.
    5. *World / Host adapters:* Strictly outside agent module ownership.
  - Retire legacy enum-switch research profiles (`ResearchProfile`) and dead flags via replace-and-delete on epochal promotion.

### 4.2 Five mandatory anti-gaming closures in Layer 0

Inspecting `Persistence.lean`, `OneStream.lean`, `Frame.lean`, `LearnedState.lean`, and `Boundary/Audit.lean` revealed five bypasses that Layer 0 closes mechanically:

1. **Kernel-owned extensional comparators:** Layer 0 (never a candidate package) defines and instantiates all three Postcondition §3 / Contract 2(d3) comparator classes — experience-free, reward-only, and bounded agents that stop learning (defined extensionally by post-cutoff memory freeze or fixed parameter/hidden-state partition), closing `declaresNothing` / `nothing_stops` and `KeepsOnly` law ring-buffer smuggling without inspecting candidate internals.
2. **Executable codecs and IR/cost-monad work extraction:** Replace candidate-supplied *work* and *resume* fields in `OneStream.Learner` with checked `Format.Exact` serialization round-trips and compiler-IR / `Costed` resource bounds.
3. **Trusted Verifier Inversion:** Hosted CI checks out the canonical `acorn-contracts` and `acorn-baseline` commits, mounts the candidate package downstream overriding its dependency lock and gate scripts, verifies `AcornVerif.Targets` type equality, and runs Regula plus transitive C-flag/float audits across all packages.
4. **Strict Mode A vs. Mode B separation:** Mode A (Frozen-Rung Competition) exposes zero internal store-overwrite hooks to game; Mode B (Pinned-Baseline Attribution, such as `#295`) keeps the baseline fixed and restricts candidate mechanisms to store-isolated `(Percept, Output)` inputs.
5. **Parameterized per-package boundary audits and departure manifests:** Replace hardcoded "Acorn.*" module lists with package-scoped namespace tiers, require zero-bias agents to typecheck polymorphically over every `Interface` (blocking direct world constants, optionally reinforced by relabeling equivariance and `Frame` non-interference), and separate the owner-admitted `Departure` register in Layer 0 from candidate-local proposed-departure manifests (`#304` context).

### 4.3 Three-speed epochal clock and 5-stage triage funnel

- **3-Speed Clock (preventing mid-flight rebase thrashing):** (1) *Continuous:* Layer 1 primitives, frozen-target proofs, and Layer 2 Campaign entries merge continuously without touching the baseline; (2) *Epochal:* `acorn-baseline` remains frozen for each release epoch (immutable tag, artifact cache, declaration pins) so 200 concurrent proof swarms keep a stable target and retain permanent historical credit, batching replace-and-delete promotions once per epoch rollover; (3) *Rare, owner-gated:* Layer 0 contracts and new world classes.
- **5-Stage Triage Funnel (keeping maintainer load bounded at 1,000 swarms):** Stage 0 eliminates spec re-audit on frozen Layer 0 targets; Stage 1 runs isolated 360 s verification plus a strict quantitative dominance or simplification gate (pruning non-dominating sidegrades automatically); Stage 2 runs four fail-fast cross-family AI rubric auditors (blind read-back, provenance/anti-gaming, prior-art/citation, and scope/reuse/anti-Frankenstein) statistically calibrated by the owner; Stage 3 uses a batched merge queue to auto-merge green frozen-target proofs, Layer 1 primitives, and Layer 2 Campaign entries while reserving Layer 0 contract changes, Discovery classifications, and Epochal Baseline promotions for the owner plus two blind cross-family referees.

## 5. Lean v4.35.0 compiler, Regula, and gate laws

Inspecting Lean v4.35.0's LCNF compiler (*Lean/Compiler/LCNF/{Visibility,PhaseExt,Basic,SpecInfo,Simp/SimpValue,InferBorrow,ExplicitBoxing}.lean*) and *Lean/Environment.lean* established exact rules for zero-overhead modular compilation:

1. **Proof opacity and C ABI efficiency are orthogonal:** Unexposed *public def* implementations hide their definitions from downstream *rfl* unfolding (isolating proof edits inside `.olean.private`), while *impureSigExt* still exports exact unboxed Float32/Float and borrowed `@&` ABIs for direct calls across module and package boundaries.
2. **Exact coarse-seam specialization recipe:** Passing a plain ops *structure* without specialization compiles to indirect `.fvar` closure calls, forcing every argument owned (destroying `RC=1` in-place updates) and boxing scalars (failing `AcornTools.Native.Resources`). Bare `@[specialize]` ignores plain structures; wiring combinators must name the ops parameter explicitly (`@[specialize ops]`) paired with `@[inline]` on small provider dictionaries (or phantom-tagged classes), while keeping heavy numerical kernels as unexposed *public def*s. Because `@[inline]`/`@[specialize]` declarations require every referenced module to be publicly imported (*checkTemplateVisibility*), restrict those attributes strictly to small seam-wiring combinators whose imports are lightweight interfaces.
3. **Regula v0.13.0 and `AcornTools` hardening (Phase 0.1–0.3) and full repo *module* completion:** Regula's *Regula.Load* already uses Lean *module* files and *OLeanLevel.private*; Phase 0.1 verifies Acorn's claimed multi-library cone and equation-lemma replay (*RG2001*) under *module* files. Phase 0.2 updates `AcornTools` to permit *expose*/*no_expose*/*specialize* attributes cleanly, block *meta* and *import all* escapes, verify canonical realPaths of all five module artifacts (`.olean`, `.olean.server`, `.olean.private`, `.ir.sig`, `.ir`), enforce `lake-manifest.json` URL+SHA locks, scan `.c`/`.trace` flags across all transitive dependency packages, migrate `AcornTools` itself to Lean 4 *module* files, and add a repo-wide *module*-enforcement audit. Phase 0.3 removes the nine central merge-conflict files by sharding `Decisions.lean`, parameterizing `Costed` over local site types, and replacing `lean/AcornTools/Native/Routes.lean` regexes with semantic IR call-graph checks. Phase 1 then migrates the packages bottom-up, culminating in Phase 1.3 completing full-repo Lean v4.35.0 *module* migration across all remaining maintained libraries (NativeApp, Entry, Bootstrap, AcornDocument), removing *allowNonModules* from `lean/lakefile.lean`, and activating 100% *module* enforcement.

## 6. Regime 2: Always-on living being and author-agnostic RSI

Combining the owner's two-regime model (2a) and external-to-RSI progression (1c) yields a **Three-Plane Operational Architecture** joined to Regime 1 by a **Compositional Bridge Theorem**:

- **Plane 1 — Hard Real-Time Foreground (Immutable TCB):** A tiny verified *StreamKeeper* Supervisor (extending `Forever.loopIO`, `Acorn.Host.Microduck.Stage`, `Pace.outcome`, and `Viewer.Supervision`) owns all external world sockets, reward delivery, monotonic clock, and transactional *F_FULLFSYNC* checkpoints, while supervising an OS-process-isolated worker executing `acorn-baseline` over framed `Format.Exact` IPC (zero shared heap; zero DSU runtime overhead). Bounded runtime self-reconfiguration inside one release (option selection, feature birth/retirement, routing modes) runs purely as total *Poly* transitions at full RC=1 speed. Plane 1 periodically emits non-blocking read-only state snapshots asynchronously to Plane 2.
- **Plane 2 — Async Suggester and Immutable Outer Verifier:** An author-agnostic Suggester — external human/AI swarms in Phase 3, or an isolated offline RSI researcher reading Plane-1 snapshots in Phase 4 — proposes `(next release, state migrator, proof bundle)` (and in Phase 4 may also refine its own offline search heuristics). Every proposal passes through the **identical immutable outer Verifier** (Lean kernel, Regula, `lean-intent`, boundary/frame audits, artifact-digest binding) to mint a linear, finite-budget *UpgradePermit*.
- **Plane 3 — Quiescent Cutover, Graded Symmetric Lenses, and Canary Rollback:**
  - *Quiescent cutover:* While the active worker runs uninterrupted, the shadow worker warms up and pre-allocates its proved memory arena; at `Stage.ready` (zero in-flight choice), *StreamKeeper* executes a verified symmetric-lens migration (*migrate* / *rollback*) with three declared knowledge-preservation grades: **Grade 1** (exact stream bisimulation), **Grade 2** (bit-for-bit preservation of all surviving contract-declared `KeepsOnly` parameters via symmetric-lens tensor `id_untouched ⊗ migrate_changed` plus neutral entry for new fields, blocking staircase resets and pretrained-weight smuggling), or **Grade 3** (explicitly owner-authorized epoch transitions using off-RT migration plus executed-transition `(percept, action)` catch-up or safe-hold windows).
  - *Probation and rollback:* The prior release binary and symmetric-lens complement stay hot across a probation window (`healthyRunMs`); any crash, deadline fault, or violation triggers instant rollback rather than halting (*Lifecycle.exhausted_stopped*), decrementing the finite upgrade budget.
- **Why this remains sound under RSI and Löb's theorem:** Every *UpgradePermit* verifies an **object-level theorem** about a concrete candidate release and migrator over a frozen snapshot without invoking self-reflection on Lean's own soundness; unbounded lifetime safety follows by external meta-level induction across the immutable supervisor; keeping reward/world/utility/verifier/corrigibility in an external OS fault domain blocks hedonistic utility rewriting and wireheading; and separating deductive safety checks from preregistered out-of-sample / shadow-canary empirical evaluation prevents optimizer's-curse cherry-picking.

## 7. Mission and Trusted Computing Base (TCB) accounting

- **Machine-checked by Lean, Regula, `lean-intent`, and `AcornTools`:** Package-level world/host/FloatLib isolation, zero `sorry`/custom axioms/`unsafe`/*partial*/metaprogramming escapes, static memory and `Costed` work bounds, `Format.Exact` round-trip serialization, kernel-owned extensional comparators, A/G + RUSC seam contracts, *VerifiedUpgrade* invariant preservation + neutral entry + knowledge preservation + rollback exactness, and artifact-digest/budget enforcement.
- **Irreducible TCB (concentrated at Layer 0 and selective promotion gates):**
  1. Steganographic replay buffers packed inside declared learned float arrays (`historian_actions`) and truthfulness of `OneStream` update reports for wholly novel architectures (cross-family referee audit at promotion).
  2. Mode-B attribution task legitimacy (`recognized_iff` in `LearnedStateFrame`, answered by referee review).
  3. Domain bias disguised inside world-agnostic pure math (mitigated by `∀ interface` polymorphism and proving one agent across multiple independent worlds: Grid, ARC-AGI-3, Microduck).
  4. Grade-3 knowledge-loss authorization, empirical canary promotion thresholds, and owner rubric calibration.
  5. Lean 4 kernel, *leanchecker*, C compiler flags, OS MMU process isolation, monotonic clock accuracy, and filesystem sync durability (`lean/os/checkpoint-sync.c`).
